# ParadigmEve private dogfood release candidate

## 2.1.9

Private dogfood checkpoint for explicit Thread activation, a self-describing fresh `%how` Thread, current Vault delivery, and the broader set of runtime/UI hardening that produced the verified 2.1.9 working build.

## Why this build exists

ParadigmEve 2.1.8 treated every Thread selected through a broad `#quilt` reference as activated. That meant a broad Quilt could inject the standing prompts of all member Threads and could trigger `%how`'s packaged manual merely because How belonged to the Quilt.

2.1.9 separates those concepts so the user's live request remains the instruction that decides what to do with broad saved context.

This tag also freezes the other integrated work that was already present in the working 2.1.9 build rather than pretending the release consists only of the Thread/Quilt slice.

## What changed

- `%thread` activates one exact Thread: its standing Thread prompt, Thread-specific opening context, and saved Pins are available to the fresh chat.
- Starting a chat directly from a Thread in the Pins/Threads UI uses the same activation behavior.
- `#quilt` contributes the saved Pins from its currently pinned member Threads but does **not** activate those Threads' standing prompts.
- `%how`'s packaged Vault/manual context is triggered only when How itself is activated, not when `#Eve` merely includes How as a member Thread.
- The pristine `%how` starter data now carries a compact activation directory for a fresh Eve/Eva: `%how`, `%appdata%`, `%expenses`, `%organize`, and the initial `#Eve` grouping. An untouched app-created legacy `%organizer` starter upgrades in place to `%organize`, preserving its durable id and Pins, while user-renamed or customized Threads stay authoritative.
- The packaged manual remains the canonical `docs/vault/*.md` payload exposed read-only at `/paradigmeve-manual`; the fresh activation directory does not duplicate the manual or depend on the original laptop's AppData.
- Windows packaging carries that current Vault under the installed `resources/docs/vault` tree. Package smoke verifies the exact Markdown page set and bytes against source, and startup mirrors the installed set into `%APPDATA%\ParadigmEve\docs\vault` while removing stale managed Markdown without touching unrelated neighboring files.
- Image-only and image-bearing chat messages can be Pinned with compact provenance locators and bounded local thumbnails; full image bytes remain owned by the existing session/event stores.
- Browser-backed local resources use purpose-bound opaque descriptors rather than exposing arbitrary native paths to Chrome.
- The semantic review heartbeat can now reach the exact owning Eve conversation as a real scheduled review turn after the earlier delivery deadlock; an explicit `chat_review_complete` receipt remains the only semantic completion signal.
- Current dogfood UI/recovery work is included in the same checkpoint: editable Thread prompts, flat Plans-style Thread/Archived pills, composer draft persistence, current Setup/startup defaults, Eve/Eva self-maintenance/AppData access, and current English/Swedish presentation.
- Bridge protocol remains **15** because this change does not alter the browser wire contract.

## Acceptance boundary

Source/tests/package/installed/live are separate evidence levels. Before this candidate is called complete:

- focused Pins/context/default-Thread tests and TypeScript must pass;
- the full repo verification gate must pass;
- the Windows x64 **debug** and **dev** packages must pass packaged-runtime smoke with the current Vault present;
- the packaged Vault page set and every Markdown file must match the tagged source bytes;
- a fresh installation should seed `%how` from shipped code and let Eva explain the pristine activation directory without relying on pre-existing `state/pins.json`.

The installed fresh-Eva behavior is a live acceptance step, not something inferred from source or installer contents alone.

## Platform notes

The release binaries are unsigned; macOS builds are also **unnotarized**. macOS requires **macOS 13 Ventura or newer**. Ad-hoc sealing verifies bundle integrity but does not establish publisher trust, so verify the matching SHA-256 checksum before running a downloaded artifact.

On Linux, prefer the DEB on Debian/Ubuntu. If a host disables **unprivileged user namespaces**, the AppImage launcher can use its documented conditional `--no-sandbox` fallback. That fallback is not the default launch mode.
