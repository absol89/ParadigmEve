# ParadigmEve 2.2.5 — ChatGPT stream attribution and recovery

## 2.2.5

2.2.5 is cumulative over the 2.2.4 dogfood line and keeps bridge protocol **15**. This release repairs
ParadigmEve's ChatGPT request attribution and reply-capture path after ChatGPT changed the structure and timing
of its conversation stream. It also hardens restart/recovery behavior so attribution repair no longer disrupts
an answer that is still being generated.

Local Windows qualification uses the x64 **debug** build. The `2.2.5` tag belongs on the exact packaged tree
that passes installed-runtime dogfood.

### Highlights

- **Exact tool-call attribution works again on ChatGPT's current stream.** Eve can prove which ChatGPT
  conversation made a connector call instead of waiting 20 seconds and falling back to Unattributed activity.
- **Early request-id sightings survive until the matching MCP call arrives.** ChatGPT can announce a request id
  seconds before the first tool call; ParadigmEve now retains that evidence instead of dropping it after one
  premature correlation lookup.
- **App restarts no longer strand the rest of a turn.** The page remembers recent request ids and can re-offer
  them when the restarted app asks to reconnect recorder evidence.
- **Attribution recovery no longer reloads a reply that is still streaming.** A live response stays intact while
  recovery waits for a safer boundary.

### Fixed

- Tool calls are attributed to their chat again on ChatGPT's current `/f/conversation` stream (ported from
  upstream chat-on-steroids #414 and #432). The handoff event names the conversation and the following
  `input_message` event carries the request id with none, so the Companion now joins them within one response
  only (another conversation in that response retires the join). A request id published before a hand-started
  chat has its route now survives the move into that chat. Previously every call waited out the identity window,
  landed in Unattributed activity and triggered repair reloads.
- The app now keeps a stream sighting until its tool call arrives. ChatGPT announces a turn's request id when the
  turn starts, seconds to minutes before the first connector call carries it, and the page sends that sighting
  only once; `/correlations` answered it `pending` and the proof was lost. The bridge now holds pending sightings
  (bounded, 15 minutes) and completes the join the moment that exact id is admitted by local MCP. Admission is
  still required, and an existing correlation is never overwritten.
- A turn that spans an app restart (for example Eve installing a build) no longer stays Unattributed for the rest of
  the turn. The page remembers the request ids it sighted on the stream (bounded, 15 minutes) and re-offers them
  when the app asks it to reconnect its recorder evidence, since the restarted app never received the turn's
  one-time announcement.
- An unattributed-activity repair no longer reloads a chat whose page reports it is streaming (upstream #433);
  it reports the repair as not done and the next pass decides. Silence and error recovery still reload.

### Reliability and recovery

- The Companion's current-page reader handles the split stream shape where conversation identity and request id
  arrive on different events in the same response.
- Request-id sightings are bounded by count and age so recovery evidence cannot grow without limit.
- A request id still gains local authority only after a real MCP call carrying that id arrives. Browser evidence
  alone cannot invent local traffic or overwrite an existing correlation.
- Existing exact-chat safety remains intact: operations that require exact Eve/Eva ownership still fail closed
  when that ownership cannot be proven.
- The 2.2.4 fixes remain cumulative, including assistant-reply capture on ChatGPT's newer render-item layout,
  stale Request Trail check-in suppression, restart-wake ordering, installed Companion refresh, and silent
  installer relaunch of a previously running ParadigmEve instance.

### Installed dogfood proof

The current Windows x64 debug build was installed over the prior dogfood build and exercised from a fresh Eve
turn. Live evidence in `app.log` showed:

- `work_context` returned `callerIdentity: "proven"` for the exact Eve session and conversation;
- the first call used a small attribution wait (`identity_ms=2`) instead of the previous 20-second timeout;
- the bridge logged that the request was attributed to the Eve conversation **from its earlier stream sighting**;
- the following tool call used `identity_ms=0`;
- no `no page evidence ... Unattributed activity` fallback was emitted for those fresh-turn calls.

The same-turn restart recovery path is covered by focused regression tests and remains a separate live-dogfood
case for the next install that interrupts an active turn.

### Local dogfood acceptance

Before tagging 2.2.5:

1. qualify the exact source with the focused stream/repair tests, typecheck and full repository
   verification;
2. build one fresh Windows x64 debug installer from that exact tree and record its SHA-256;
3. install it over 2.2.4 and let the installer own ParadigmEve shutdown/restart;
4. confirm connector calls from the Eve chat are attributed to that chat without the identity wait
   (no `request attribution: no page evidence` for them in `app.log`) and that no attribution repair
   reloads the chat while it streams.

### Known follow-ups

- Open ChatGPT tabs still need their page-side reader refreshed after an update; automatic safe re-injection of
  the updated `usage.js` into already-open tabs is the next update-path fix.
- Turn/Stop detection on ChatGPT's newest layout still needs its dedicated verification pass, including
  translated-page variants.
- New ChatGPT stream-error wording needs to be folded into the error classifier.
- Reply timestamps for older backfilled exchanges currently reflect the local recording time rather than the
  original provider-authored time.

### Cross-platform release contract

The public workflow still targets Windows x64/arm64, macOS x64/arm64, and Linux x64/arm64. macOS 13
Ventura or newer is the supported floor. Current macOS artifacts are **unsigned** and
**unnotarized** development/release-build outputs unless a later publishing process explicitly
establishes signing and notarization.

Linux keeps the documented static sandbox fallback for hosts where unprivileged user namespaces are
unavailable. The explicit `--no-sandbox` escape hatch is a last-resort compatibility path for those
hosts, not the default launch mode.

The reviewed public workflow artifact names remain:

- `ParadigmEve-Setup-x64.exe`
- `ParadigmEve-Setup-arm64.exe`
