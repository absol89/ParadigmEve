# ParadigmEve v2.4.1 — Smoother first run

## 2.4.1

2.4.1 fixes what a new user met during onboarding of 2.4.0: automatic Companion loading on
Windows, a first message sent without a model choice, the first Eve chat not being claimed,
and a heartbeat side chat whose title made it look like a working coding agent. Everything in
the [2.4.0 notes](v2.4.0.md) still applies.

**Status:** this is a Windows x64 self-testing candidate. The `v2.4.1` GitHub tag is set only
after that build passes self-testing, and the GitHub release page then shows the tagged commit.

### Onboarding: automatic Companion loading on Windows

- The Windows folder picker's folder field is a Win32 edit control that current Windows builds
  expose to UI Automation without a value pattern, so the automatic step failed with
  `UI_VALUE_UNSUPPORTED` and stopped at step 2. Setup now enters the Companion folder from the
  keyboard: it selects the field's text and types the folder, pastes it if typing is rejected,
  and accepts with Select Folder, or Enter when that button is not exposed.
- The Companion folder is the per-user copy the app keeps in its data folder
  (`%APPDATA%\paradigmeve\extension` on Windows), refreshed from the installed package on every
  start, so Chrome keeps loading the same path across updates.
- The Extensions page is found by Chrome's control ids, or by the visible **Load unpacked** and
  **Developer mode** names when a Chrome build does not expose those ids.
- When a step still cannot finish, setup hands over to that step's manual instructions, which
  show the folder with a Copy button. Automatic Companion loading remains Windows-only; macOS and
  Linux use the manual steps.

### First message: choose a model once

- A user who has never chosen a model is asked to choose one before the first message is sent.
  Enter, Send and Start goal open the model menu and keep the draft; nothing is sent with
  whatever ChatGPT happened to have selected. The choice is saved, so later new chats start on it.
- The menu recommends a starting model from the models this ChatGPT account offers: Sol 5.6
  Medium on Plus, GPT-6.1 High on Pro when the account's picker lists that step, otherwise
  ChatGPT default. The recommendation is never applied without the user's click.
- Free and Go accounts, whose ChatGPT has no model picker, are never asked and send on ChatGPT's
  default model.

### First Eve chat

- On a fresh install the first chat now claims Eve without clicking New Chat first, even when the
  heartbeat review already has its own chat. `@Eve ` is prefilled once; deleting it keeps it
  deleted.

### Heartbeat review chat

- The app-owned heartbeat review chat is shown as **Heartbeat review** with a **Heartbeat** label.
  ChatGPT titled it from the connector instructions ("Coding agent collaboration"), which made a
  read/review-only chat look like one that could edit and run things. Its title inside ChatGPT
  itself is unchanged.

### Platforms and preview downloads

The release workflow targets the following downloadable artifacts. Their presence
does **not** mean every platform has been built, smoke-tested,
uploaded, or published:

- `ParadigmEve-Windows-x64-debug.exe` — Windows x64 installer.
- `ParadigmEve-Windows-arm64-debug.exe` — Windows ARM64 installer.
- `ParadigmEve-macOS-x64-debug.dmg` — Intel Mac installer.
- `ParadigmEve-macOS-arm64-debug.dmg` — Apple silicon Mac installer.
- `ParadigmEve-Linux-x64-debug.AppImage` — Linux x64 portable build.
- `ParadigmEve-Linux-x64-debug.deb` — Linux x64 package.
- `ParadigmEve-Linux-arm64-debug.AppImage` — Linux ARM64 portable build.
- `ParadigmEve-Linux-arm64-debug.deb` — Linux ARM64 package.
- `ParadigmEve-Extension.zip` — standalone browser Companion extension.
- `ParadigmEve-Native-Sources.tar.gz` — bundled native-library source archive.
- `SHA256SUMS.txt` — checksums for the public assets after packaging.

**macOS 13 Ventura or newer** is the supported Mac baseline. macOS builds are
**unsigned and unnotarized**; Gatekeeper may warn, and a downloaded candidate
must be checked against its SHA-256 digest before installation.

Linux AppImages normally rely on the sandbox. On hosts where
**unprivileged user namespaces** are unavailable, the launcher may fall back to
`--no-sandbox`. This is a reduced-isolation compatibility fallback, not
the recommended default. On Debian/Ubuntu, the DEB package is preferable on
hosts that cannot provide the sandbox.
