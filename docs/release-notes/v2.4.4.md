## Candidate 1: transcription diagnostics and updater warning suppression

- Preserve the exact selected OpenAI or Groq Cloud transcription provider. Cloud
  errors are reported using bounded categories and HTTP status, not provider
  response bodies or API credentials. The user sees actionable failure context
  in the transcription card; the job writes a minimal diagnostic receipt for
  future debugging, and Eve's Activity log records the sanitized failure.
- No automatic re-upload of ambiguous failed audio POST requests. Only enabled
  transcription avenues participate in the existing visible fallback order.
- A six-hour-cached GitHub updater fetch failure is still visible as a failed
  update check but no longer repeats the same warning every 60-second local
  polling pass. GitHub Latest/checksum authority and the six-hour request
  ceiling are unchanged.
- GPU and cloud execution provenance remain separate. Recording and transcript
  audio remain user-controlled; these fixes do not authorize new uploads.

## Candidate 2: local archive efficiency and current `%how` guidance

- Static Archive Browser refresh now reuses hash-verified on-disk search and
  transcript segments for unchanged conversations. Only dirty chats are
  re-rendered when the positional navigation map remains unchanged. Unsafe,
  missing, or modified fragments and changed navigation maps fall back to
  canonical event scanning. Explicit full Rebuild still verifies all evidence.
- Automatic background static-site refresh is capped at once per 30 minutes
  rather than once per five minutes, while opening Archive can refresh on demand.
  These are local filesystem/Node.js operations, not model-token requests.
- `%how` now receives a small version-aware entry guide rather than an entire
  historical manual as startup context. All older Vault pages remain available
  for explicit reading, labelled as historical evidence where appropriate.
- Candidate 2 was installed locally; its installed `app.asar` matched the
  packaged payload. A subsequent site-only refresh reused 34 unchanged chats
  and re-rendered one. This is partial live evidence, not full resource or
  reliability acceptance.

## Candidate 3: failed-message action state and layout

- A user-authored message that expired before browser pickup, with **no**
  browser owner, offer, Send authorization, native message id or receipt, shows
  one **Force Send** recovery action plus **Dismiss**. It reuses the *same*
  durable message id and is still refused if the exact chat, browser, model,
  reasoning effort, another pending user input or human draft makes Send unsafe.
- A claimed/ambiguous failed send instead offers **Restore to composer**
  (manual review) plus **Dismiss**; it never gains Force Send or an automatic
  resend. An ordinary queued row retains its guarded controls.
- Buttons now occupy a shared flex action rail with reserved width and spacing,
  rather than stacking both recovery icons at the same absolute CSS offset.
  Dismiss affects the notice only; it does not delete a durable receipt.
- Source regression: 374 tests passed across the renderer timeline, input
  startup and session-input suites, TypeScript passed, and the diff is clean.
  C3 still needs an installed UI check at narrow widths and an exact
  *unclaimed* timeout, without re-sending historical messages as a test.

## C5–c7 and subsequent source reliability fixes

- **Exact identity:** shared Eve access is authorization, not Prime/worker
  identity. Exact Companion proof binds worker conversation, session, run and
  invocation. Unattributed calls do not silently enter Prime Plans; worker
  heartbeat keys cannot impersonate Prime.
- **Protected recovery:** fresh document re-registration avoids a reload to
  manufacture proof. All reload-capable repairs recheck selection, Voice,
  drafts, generation, navigation and exact conversation evidence. Uncertain
  pages stay untouched; interrupted live streams have one bounded Continue
  path without replaying the original message.
- **Archive/Plans:** static publication restores restart freshness, retries
  failures while retaining the previous site, and reuses unchanged fragments.
  Oversized single-line Plan-catalog coverage retains the 512 KiB reader cap.
- **Post-c7 source only:** native Send re-arms passive request-ID observation
  before click/submit/Enter; the Compact & Resume watchdog preserves an old
  chat still generating its handoff; input logs separate row age, pickup wait
  and claim-to-ACK latency.
- **Installed evidence:** c7 Windows x64 debug dogfood observed exact Prime
  and worker attribution, independent Eve tool calls and no duplicate replay
  in a traced held input. These observations do not cover the post-c7 source.

## Historical Candidate 1–3 promotion findings (superseded where noted)

- **Archive startup/shutdown:** c2 still performs a full archive rebuild at
  both lifecycle boundaries. One installed startup indexed 11,487 documents
  across 35 sessions and reached roughly 921 MiB process RSS during indexing.
  This is separate from the now-incremental static-site refresh; review resource
  impact before declaring the optimization accepted.
- **Prime attribution and Request Trail:** page-evidence matching has left
  real tool calls Unattributed and some accepted Plan requests without an
  exact Request Trail refresh. A passing build does not prove this solved.
- **Brave UIA:** the desktop helper's strict browser-root detection can refuse
  a Brave accessibility tree. No unverified fallback that might select an old
  or hidden tab is included.
- **Browser pickup:** c3 fixes the icon/state *presentation* but does not claim
  to eliminate the underlying 60-second browser pickup failure.
- These were c3-era observations, not claims about the current tree. The
  checkpoint must retain the verified cumulative fixes and the distinct
  post-c7 acceptance gates above.
