# ParadigmEve 2.4.6 — Local model choice and EVE-Al

## 2.4.6

> Local Windows candidate development on `release/2.4.6`, based on published 2.4.5.
> Source, packaged candidate, installed bytes, and live EVE-Al completion are separate
> evidence. No public release, tag, push or Latest promotion is implied.

## Earlier c1 scope

- Session-local model preference survives history reload and Compact & Resume without
  an old renderer cache overriding the durable choice; only a new chat takes the
  current global default.
- Local Ollama chats use native `/api/chat` with context sized for their history,
  Thread opening context persists across turns, and the EVE-Al contestant suite
  ships read-only with a unique, app-owned output folder per local run.

## c2 source scope

- Adds an explicitly selected **llama.cpp** provider alongside Ollama, using the
  standalone, loopback-only OpenAI-compatible API at `127.0.0.1:8080/v1`.
  Live model discovery, session routing, provider-history consent and local-only
  privacy stay separate from Ollama and OpenRouter. No backend fallback or
  automatic model change occurs.
- The companion native llama.cpp launcher supports context, GPU layers, thread
  count, batch size and sampling controls. The portable runtime and GGUF are
  optional files outside Eve's installer; they are not secretly installed,
  downloaded or launched at login. See [local llama.cpp guide](../local-llamacpp-lfm3.md).
- Ollama v0.40.13's strict tool parser receives object-compatible projections
  of `file_action` and `pins` union schemas, removing a 500 error before a local
  agent could call tools. The original Core/Zod argument validators still enforce
  every action; OpenRouter keeps its full JSON Schema unions.
- Starter prompts that insert hotlinks such as `%how`, `%expenses`, `%eveal`, and
  `%plans` no longer put a period immediately after the reference, including
  Swedish and Spanish translations. User-authored punctuation remains valid.
- Adds focused regression checks for local tool schemas and starter prompts,
  preserving the established Ollama model list, credentials and routing.
- Reconciles previously uncommitted reliability work from the 2.4.5 development tree:
  late-recovered ChatGPT messages retain their real order in the session archive;
  browser model/Think picker preparation is bounded before the Send claim expires,
  and expired claims and late page failures become diagnostic log entries without
  silently retrying delivery.
- Carries forward skill selection guidance (shortlist plausible procedures, with
  no Skill a valid choice), debugging instructions to test competing explanations,
  and the associated regressions. None of these instruct Eve to rewrite user Skills.

## c5 integration scope (source and candidate, not installed acceptance)

- Native local Ollama `/api/chat` now streams NDJSON output instead of holding an entire
  generation until the response ends. Bounded parsing assembles content and tool calls only
  after Ollama's terminal `done` event, with explicit failures on truncation and malformed
  responses. This addresses the five-minute `fetch failed` seen when LFM3 had generated
  about 6,142 tokens during `%eveal`; the installed app still needs a long-run replay.
- EVE-Al v0.3 expands the read-only contestant suite to 80 points with Swedish comprehension,
  instruction following, general-fix, evidence-based pushback and calibration. The seeded
  scorer and answer-key machinery live in `agent-arena/v0.3/`, outside the packaged suite;
  practice material is generated and checked deterministically.
- Browser recovery now distinguishes a genuine unanswered repair handout from a page held by
  the human's active tab, draft, typing, Voice or tool approval. Holds remain visible and
  queued without exhausting the unclaimed-offer budget. Stale error reports from superseded
  turns cannot trigger repairs against a newer turn.
- Model picker evidence may skip unreadable *unselected* offerings while requiring exact
  readable identity for the selected option; the four-provider composer menu fits within
  narrower windows. Session finish ignores late non-final notes for turns already completed.
- Goal/Loop decisions on custom OpenAI-compatible endpoints can respond to an explicit
  format-unsupported HTTP 400 by stepping from `json_schema` to `json_object`, then to
  JSON-in-words without a format parameter. The response remains validated; other failures
  and OpenRouter routing do not silently downgrade.

## Acceptance boundaries

- The initial uncapped LFM3 `%eveal` run on the previously installed build was
  blocked by Ollama's root JSON Schema parser; c2 changes require a new installed
  run before claiming that tool execution or suite completion succeeds.
- Text tool calling and source tests do not establish safe unrestricted agent
  behavior, 64K-content recall, or performance superiority. The local hardware
  baseline and two-runtime measurements are recorded separately.
- Local debug Windows installer candidates are unsigned. Only an explicitly
  verified c2 installation and runtime smoke can be called locally installed;
  cross-platform artifacts and public publication require separate gates.
- The c5 source tests and package checks do not establish a successful installed LFM3
  `%eveal` 80-point run, browser-repair recovery, or correctness of a held-out challenge.

## Platform and publication notes

- Windows debug installers are **unsigned**. macOS debug DMGs remain **unsigned and
  unnotarized** and require **macOS 13 Ventura or newer**; no macOS install is
  claimed by this Windows development run.
- On Linux hosts without unprivileged user namespaces, the documented conditional
  fallback is `--no-sandbox`, which weakens Chromium sandbox isolation. Prefer
  enabling unprivileged user namespaces and the secure sandbox when possible.
