# ParadigmEve 2.4.6 — Model integrity, local agents, and recovery reliability

## 2.4.6

ParadigmEve 2.4.6 strengthens the boundaries between ChatGPT, local models, provider routes,
durable sessions, and setup recovery. The release focuses on keeping the user's explicit model
and provider choices intact while improving Ollama/llama.cpp execution and the EVE-Al local-agent
evaluation path.

Source/tag publication, downloadable release artifacts, installed bytes, and live acceptance on
each platform remain separate evidence. Consult GitHub Releases for packages that are actually
published for download.

## Model and provider integrity

- Established chats preserve their explicit composer model and reasoning choice. New Chat owns the
  global default; restoring history or Compact & Resume does not silently replace an established
  session's choice with a newer global picker value.
- Provider switches rebuild Thread context and tool instructions for the destination route. Local-only
  EVE-Al suite/run paths do not leak into remote-provider prompts.
- Ollama **Think** and **Context** are stored per exact local model. The picker and Send path read the
  same durable values, and clearing Context returns that model to automatic context sizing.
- Cold/restored sends wait for pending preference writes and model-route discovery before enqueueing,
  instead of racing ahead with stale settings.
- The shared Send/Stop control remains responsive during that preparation window: it shows an exact
  transient Stop state without creating a duplicate durable input or weakening prepared-plan
  exactly-once behavior.
- An explicitly selected llama.cpp route remains independent from Ollama. Discovery, local-only
  handling, consent, and session routing are separate, with no silent provider fallback.

## Local Ollama and llama.cpp execution

- Ollama chats use native `/api/chat` with an explicitly managed context window so system
  instructions, activated Threads, and tool schemas are not silently cut from the front of longer
  prompts.
- Ollama's stricter tool-schema parser receives object-compatible projections for union-heavy tools;
  Eve's original argument validators remain authoritative at execution time.
- Local Ollama output is parsed from streaming NDJSON through the terminal `done` event rather than
  holding a whole generation until completion.
- Ollama and llama.cpp requests use Node's HTTP transport, avoiding the five-minute response-header
  timeout that could terminate a long prompt before the first generated token arrived.
- Image payload bytes no longer inflate automatic text-context allocation.
- Local agent runs retain the bounded tool-round limit but reserve a final-answer completion step
  afterward. That final step cannot perform additional tool side effects.

## EVE-Al Quick reveal

- `%eveal` exposes the read-only contestant suite at `/paradigmeve-eveal` while keeping answer keys and
  protected grading material out of the packaged suite.
- EVE-Al v0.3 expands the deterministic evaluation to 80 points, covering coding pitfalls, Swedish
  comprehension, instruction following, general fixes, evidence-based pushback, and calibration.
- Each local evaluation gets its own app-owned run directory. After reading the suite, writes and
  commands are scoped to that run folder; `/eveal-run` in command text resolves to the same location.
- The EVE-Al run directory is allowed without granting a local contestant blanket access to the rest
  of ParadigmEve's AppData. Installed-suite self-maintenance paths remain protected.
- Thread opening context remains available on later local-chat turns and when starting a local chat
  from a Thread even if the suggested opening draft is replaced.

## Guided setup and recovery

- Automatic setup and manual recovery no longer mutate the same setup state concurrently.
- Manual recovery remains available after an automatic provider failure instead of restarting the
  failed automatic path.
- A successful manual recovery clears stale automatic-failure presentation state while preserving the
  durable setup result.
- The real Windows folder picker path is exercised through focus, replace, and typed path entry with
  actual picker disappearance as the receipt.
- Deterministic real-Chrome smoke coverage exercises the automatic happy path, Companion absence and
  later presence, automatic-failure fallback, manual recovery, and Stop while an exact provider
  request is pending.

## Browser, delivery, and session reliability

- Browser recovery distinguishes an unanswered repair handout from a page being actively used by the
  human for typing, drafts, Voice, or provider approval. A hold stays visible without being treated as
  a failed delivery attempt.
- Superseded browser/page errors cannot trigger repair against a newer turn.
- Late-recovered ChatGPT messages preserve their real order in the durable session archive.
- Model-picker preparation is bounded before the Send claim expires; late failures become diagnostic
  evidence rather than an automatic duplicate send.
- Session finish ignores late non-final notes for turns already completed.
- Goal/Loop decisions on custom OpenAI-compatible endpoints may step down only when the endpoint
  explicitly rejects a response-format mode, while the returned content remains validated.

## Runtime and dependency updates

- Electron 43.8.6 embeds Node 24.22.1 and Chrome 150.
- Commands on a machine without a system Node can use Eve's bundled Node 24 runtime.
- When a plugin genuinely needs npm/full Node and it is unavailable, Eve can offer the official
  Node.js 24.22.2 LTS installer after explicit user consent and verifies the pinned SHA-256. Nothing
  is silently installed.

## Acceptance boundaries

- Model/tool-call tests do not establish that every local model is capable, safe, fast, or accurate.
  EVE-Al measures the tested model/run; Eve does not infer quality from a model's narration alone.
- ChatGPT approval cards remain provider-owned and require the user's decision. Eve does not bypass or
  auto-accept them.
- Native subagents are not claimed as an unattended background worker mechanism unless an active
  parent conversation and exact receipts prove the work occurred.
- A tagged source commit does not itself publish installers or promote GitHub Releases `Latest`.
- Windows debug installers are unsigned. macOS debug DMGs are unsigned and unnotarized and require
  macOS 13 Ventura or newer.
- On Linux systems without unprivileged user namespaces, `--no-sandbox` is a documented fallback but
  weakens Chromium sandbox isolation; enabling user namespaces and retaining the sandbox is preferred.
