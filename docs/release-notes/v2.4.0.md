# ParadigmEve 2.4.0 — Transcription settings

## 2.4.0

**In development; not packaged or published.** `release/2.4.0` branches from the published
`v2.3.9` and collects 2.4.0 fixes and features until release. Nothing below has been installed or
dogfooded yet. Beta builds are unsigned.

### Platforms and planned public downloads

The release workflow is designed to build the following downloadable artifacts.
Their presence in this list does **not** mean they have been built, smoke-tested,
uploaded, or published:

- `ParadigmEve-Windows-x64-debug.exe` — Windows x64 installer.
- `ParadigmEve-Windows-arm64-debug.exe` — Windows ARM64 installer.
- `ParadigmEve-macOS-x64-debug.dmg` — Intel Mac installer.
- `ParadigmEve-macOS-arm64-debug.dmg` — Apple silicon Mac installer.
- `ParadigmEve-Linux-x64-debug.AppImage` — Linux x64 portable build.
- `ParadigmEve-Linux-x64-debug.deb` — Linux x64 package.
- `ParadigmEve-Linux-arm64-debug.AppImage` — Linux ARM64 portable build.
- `ParadigmEve-Linux-arm64-debug.deb` — Linux ARM64 package.
- `ParadigmEve-Extension.zip` — standalone browser Companion extension.
- `ParadigmEve-Native-Sources.tar.gz` — bundled native-library source archive.
- `SHA256SUMS.txt` — checksums for the public assets after packaging.

**macOS 13 Ventura or newer** is the supported Mac baseline. macOS builds are
**unsigned and unnotarized**; Gatekeeper may warn, and a downloaded candidate
must be checked against its SHA-256 digest before installation.

Linux AppImages normally rely on the sandbox. On hosts where
**unprivileged user namespaces** are unavailable, the launcher may fall back to
`--no-sandbox`. This is a reduced-isolation compatibility fallback, not
the recommended default. On Debian/Ubuntu, the DEB package is preferable on
hosts that cannot provide the sandbox.

### New: Settings → Transcription

ParadigmEve gains a Transcription section that chooses where meeting and interview recordings are
turned into words. Telling speakers apart always runs on this computer, whichever option writes the
words.

| Option | Default | What it means |
| --- | --- | --- |
| GPU | On, priority 1 | Fastest when a supported graphics card is present. Audio stays on this computer. |
| Local | On, priority 2 | Runs on the processor; works everywhere. Audio stays on this computer. |
| Cloud (Groq) | Off, priority 3 | Uploads the recording's audio to Groq for the words. |

- Each option has a switch and a whole-number priority from 1 to 99. The lowest enabled number is
  tried first; an option that cannot run on this computer is skipped, never reordered.
- Enabled options must have different numbers, and at least one option must stay on.
- Cloud can only be switched on while a Groq API key is stored. The key is entered in the same masked
  field style as the other credentials and kept in the OS credential store (`safeStorage`); it never
  reaches the renderer or the config file. Removing the key switches Cloud off in the same step.
- The key slot is new (`transcriptionGroqApiKey`). The existing OpenAI key cannot be reused: setup
  creates it restricted to Tunnels.
- A damaged or pre-2.4.0 config falls back to the defaults per option; a damaged Cloud entry always
  comes back switched off.

This release adds the settings and their validation. The transcription engine itself (whisper.cpp
with local speaker separation) is still developed separately and is not bundled yet.
