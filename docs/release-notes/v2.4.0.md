# ParadigmEve 2.4.0 — Windows preview and transcription

## 2.4.0

### In development: automatic file-format broker discovery

The upcoming 2.4.0 source work directs Eve to discover its built-in file-format broker automatically when a user asks to open, edit, proofread, convert or work with DOCX documents, PDFs, spreadsheets or slide presentations. This is intended to apply in every fresh conversation without requiring a special command, prior context or an explanation of Eve's available tools.

Eve should check the broker's actual provider capabilities before recommending the installation of a separate document editor. File edits must preserve the original and operate on a local copy; fidelity limitations and potential feature loss require appropriate preflight checks and consent. Opening a visible native editor or installing one remains an explicit, user-controlled action rather than an automatic consequence of requesting file work.

**Release status:** This is development work for a future 2.4.0 build. Do not interpret this section as confirmation that these instructions or capabilities are included in the currently installed candidate, a published installer or any specific platform build.

### New: Settings → Transcription

ParadigmEve gains a Transcription section that chooses where meeting and interview recordings are
turned into words. Telling speakers apart always runs on this computer, whichever option writes the
words.

| Option | Default | What it means |
| --- | --- | --- |
| GPU | Off, priority 1 | Runs on the graphics card through Vulkan. It can only be switched on after Eve has tested the card on this computer. Audio stays on this computer. |
| Local | On, priority 2 | Runs on the processor; works everywhere. Audio stays on this computer. |
| Cloud (Groq) | Off, priority 3 | Uploads the recording's audio to Groq for the words. |

- Each option has a switch and a whole-number priority from 1 to 99. The lowest enabled number is
  tried first; an option that cannot run on this computer is skipped, never reordered.
- Enabled options must have different numbers, and at least one option must stay on.
- Cloud can only be switched on while a Groq API key is stored. The key is entered in the same masked
  field style as the other credentials and kept in the OS credential store (`safeStorage`); it never
  reaches the renderer or the config file. Removing the key switches Cloud off in the same step.
- The key slot is new (`transcriptionGroqApiKey`). The existing OpenAI key cannot be reused: setup
  creates it restricted to Tunnels.
- A damaged or pre-2.4.0 config falls back to the defaults per option; a damaged Cloud entry always
  comes back switched off.

### GPU transcription

- Windows x64 bundles a second whisper.cpp build with the Vulkan backend, alongside the processor build.
  Users only need their normal graphics driver; no Vulkan SDK or CUDA toolkit.
- Before the GPU switch can be turned on, Eve runs a small test calculation on each graphics card and
  checks the answer. If no card passes, the switch stays disabled and Settings says why: no Vulkan
  driver, no usable card, or a build without GPU support.
- Each finished job records what really ran: the backend (`vulkan` or `cpu`), the card's name, and any
  fallback with its reason. Eve reads this from whisper.cpp's own log, never from the requested
  setting. A job Eve sends to the GPU never quietly retries on the processor; if the GPU run fails, the
  next enabled option runs and the job lists the failure.
- macOS (Metal) and Linux (Vulkan through the system `libvulkan.so.1`) GPU builds are planned. Until the
  engine is packaged there, those platforms report GPU as unavailable.
- Build inputs for the Vulkan backend (shader compiler, headers, loader import library) live
  extracted and checksummed in `transcription-engine/third_party/vulkan-build`, with their licences
  and rebuild recipe. None of them ship in the installer.
- First use downloads the pinned speech and speaker models and FFmpeg into Eve's data folder and
  checks each SHA-256 before use.
