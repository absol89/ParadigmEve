# ParadigmEve private dogfood release candidate

## 2.1.6

Recovery-focused Windows dogfood candidate for Compact & Resume successor chats.

## What changed

- Fresh worker and Compact & Resume pages now recover when Chrome's MV3 service worker delivers the command to the app but loses only the reply on the way back to the content script. The same marked document retries `/commands/redeem` after a short bounded wait and receives the already-durable command lease instead of leaving a blank successor tab until the bridge deadline.
- The complementary pre-redeem failure is covered too: if Chrome created the marked successor but no Companion redeem arrives, ParadigmEve reloads that **same exact marked tab once** after a bounded wait **only when no live Companion recorder answers in it**. A live recorder is never overridden by a blind reload, preserving its draft/user-interaction safety decision. If the tab changed route it is left alone; if the reload still produces no redeem, the command fails explicitly instead of waiting out the generic 90-second timeout.
- If ChatGPT itself restores that exact app-opened fresh document onto an existing `/c/...` route before the first redeem, ParadigmEve never types the handoff into that conversation. When the page is still untouched, empty, idle, attachment-free and carries the exact command marker, it uses ChatGPT's native **New Chat** control to return the same document to a proven empty home and only then redeems. A pre-existing `/c/...?...clf=` tab, user interaction or a draft remains fail-closed and is never reset.
- The recovery is deliberately narrower than retrying the handoff itself. It creates no second tab, does not re-click Send, and uses the same `RUN_ID`, command id and continuation claimant. Once destination dispatch is armed, the existing no-replay rules are unchanged.
- The observed 2026-09-14 failure matched the upstream Chat On Steroids issue #167 family: the replacement tab was opened, ParadigmEve later logged `the chat this app opened did not report back in time`, and reloading a stranded successor is the known manual escape hatch for a lost redeem reply.
- ParadigmEve already contains the separate early-destination/shadow-session protections discussed in upstream PRs #224 and #231; 2.1.6 keeps those guards and addresses the remaining service-worker reply boundary instead of rolling them back.
- Bridge protocol remains **14** because no wire payload changed.

### Expected release artifacts

Canonical shipping target names for a completed 2.1.6 release remain:

- `ParadigmEve-Setup-x64.exe` — Windows x64
- `ParadigmEve-Setup-arm64.exe` — Windows on Arm
- `ParadigmEve-macOS-x64.dmg` · `ParadigmEve-macOS-x64.zip` — macOS Intel
- `ParadigmEve-macOS-arm64.dmg` · `ParadigmEve-macOS-arm64.zip` — macOS Apple silicon
- `ParadigmEve-Linux-x64.AppImage` · `ParadigmEve-Linux-x64.deb` — Linux x64
- `ParadigmEve-Linux-arm64.AppImage` · `ParadigmEve-Linux-arm64.deb` — Linux ARM64
- `ParadigmEve-Extension.zip` — standalone companion extension
- `ParadigmEve-Native-Sources.tar.gz` — native source archive, dependencies, notices and build/replacement instructions
- `SHA256SUMS.txt` — SHA-256 checksums

> **macOS:** publisher-unsigned and unnotarized; verify the checksum once artifacts exist. Requires macOS 13 Ventura or newer. Ad-hoc sealing provides bundle integrity, not publisher trust.
> **Linux:** prefer the DEB on Debian/Ubuntu. Where unprivileged user namespaces are disabled, the AppImage launcher can fall back to `--no-sandbox`.

## Dogfood acceptance

The laptop's required **-debug** Windows x64 candidate was built successfully on 2026-09-14 as `ParadigmEve-Setup-x64-debug.exe` (155,051,152 bytes), with embedded FileVersion/ProductVersion `2.1.6` and SHA-256:

`3E8661EEC7E4251A4FEBA5F5C9545943DCA92ABBE99083F208AC813E8968734A`

Before calling 2.1.6 ready for the new PC, install that candidate over the running ParadigmEve copy. Then exercise Compact & Resume in a real long chat and verify that the successor chat receives its bootstrap, commits the same durable Eve identity/session, and does not create a duplicate successor tab. Keep DevTools open for the first rehearsal and record whether ChatGPT still emits its own `/backend-api/f/conversation/resume` 405; that provider request is not a ParadigmEve endpoint and should no longer be allowed to strand our local redeem path.
