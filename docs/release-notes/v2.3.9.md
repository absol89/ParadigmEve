# ParadigmEve 2.3.9 — Release-candidate verification

## 2.3.9

**Not yet published.** This document describes candidate changes and test goals,
not verified behavior in an installed app. The published 2.3.8 release remains
unchanged. Beta builds are unsigned.

### Platforms and planned public downloads

The release workflow is designed to build the following downloadable artifacts.
Their presence in this list does **not** mean they have been built, smoke-tested,
uploaded, or published:

- `ParadigmEve-Windows-x64-debug.exe` — Windows x64 installer.
- `ParadigmEve-Windows-arm64-debug.exe` — Windows ARM64 installer.
- `ParadigmEve-macOS-x64-debug.dmg` — Intel Mac installer.
- `ParadigmEve-macOS-arm64-debug.dmg` — Apple silicon Mac installer.
- `ParadigmEve-Linux-x64-debug.AppImage` — Linux x64 portable build.
- `ParadigmEve-Linux-x64-debug.deb` — Linux x64 package.
- `ParadigmEve-Linux-arm64-debug.AppImage` — Linux ARM64 portable build.
- `ParadigmEve-Linux-arm64-debug.deb` — Linux ARM64 package.
- `ParadigmEve-Extension.zip` — standalone browser Companion extension.
- `ParadigmEve-Native-Sources.tar.gz` — bundled native-library source archive.
- `SHA256SUMS.txt` — checksums for the public assets after packaging.

**macOS 13 Ventura or newer** is the supported Mac baseline. macOS builds are
**unsigned and unnotarized**; Gatekeeper may warn, and a downloaded candidate
must be checked against its SHA-256 digest before installation.

Linux AppImages normally rely on the sandbox. On hosts where
**unprivileged user namespaces** are unavailable, the launcher may fall back to
`--no-sandbox`. This is a reduced-isolation compatibility fallback, not
the recommended default. On Debian/Ubuntu, the DEB package is preferable on
hosts that cannot provide the sandbox.

### What we are testing

- **Readable Activity diagnostics.** The Activity **Timing: Off** default stops verbose desktop
  helper, queue, and screenshot timing entries before they consume the 500-entry in-memory
  log. Activity can enable timings live for profiling without silencing failures or warnings;
  the preference survives restart. Historical file logs are not rewritten.

- **Replies that load late or fail to render in ChatGPT.** The Companion can read
  assistant messages from the exact typed turn, including interim GPT-6 text,
  even when some of ChatGPT's rendered message components are unavailable.
  Completed-turn evidence must remain distinct from in-progress commentary.
- **Your messages during a long reply.** For supported non-Pro turns, text
  typed during generation uses ChatGPT's composer rather than disappearing
  inside a tool result.
- **More conservative Compact & Resume.** The recovery loop waits while the
  source turn is still proven active instead of exhausting its retry allowance
  on a busy ChatGPT page.
- **Clearer initial setup.** In ChatGPT, visit
  **[chatgpt.com/plugins](https://chatgpt.com/plugins)**, press **Add** in the
  **top-right corner**, and select **Add custom MCP server**. The new instruction
  is also provided in Swedish and Latin American Spanish. Leave the normal
  permission settings in place unless you want to change them yourself.
  Developer mode is a fallback only for older ChatGPT interfaces.

### c1 dogfood acceptance

The candidate is not ready for release merely because automated tests pass.
Verify all of the following using the installed Windows c1 candidate:

1. From a fresh setup with no explicit model selection, the very first
   assistant answer appears in Eve and in its durable archive.
2. With a longer GPT-6 answer, interim text, tool calls and the eventual final
   reply are attributed to the correct original turn and appear once each.
3. When a ChatGPT response temporarily cannot load, Eve does not invent a
   completed turn; on recovery, available messages reconcile without duplicates.
4. A user message sent during generation arrives as that user's actual message.
5. Compact & Resume completes without destructive busy-tab reloads,
   duplicate sends, or lost conversation ownership.
6. Existing ChatGPT tabs, voice sessions and draft messages retain focus and
   their content. The Companion does not navigate away from them.
7. The `/plugins` buttons, onboarding localization, and default permissions
   work for a non-developer user.

### Known limitations and release gate

ChatGPT's browser-side "This response couldn't load" error, React hydration
messages, Statsig POST failure, and delayed Live transcription were observed
but **not** conclusively attributed to ParadigmEve. Browser/network failure
diagnosis must not be confused with Eve's ability to capture a response that
ChatGPT actually exposes.

Await the installed-app acceptance results and explicit release authorization.
Do not retag v2.3.8, auto-install c1, or represent c1 as a public release.
