# ParadigmEve 2.2.3 development dogfood

## 2.2.3

2.2.3 is the post-Angel private dogfood line. It is cumulative over the stable 2.2.2 Angel release
and keeps bridge protocol **15**. Local Windows qualification uses the x64 **debug** build; a dirty
`--allow-uncheckpointed` package is development evidence only and is not an immutable public release
candidate until the exact source is checkpointed and the normal release gates are repeated.

### What changed

- Pins now presents the current Concept / Hotlink / Thread model from durable content while keeping
  every Pin in exactly one Thread and wider grouping in `#Quilt`. Create begins as an unsaved local
  editor, Links remain optional metadata, and current preview/privacy/density controls stay UI-owned.
- The Pins workspace uses the new pink heart memo + pushpin heading icon. Message-level Pin actions
  live with their authored send, including the readable `attachment → Pin → message text` order.
- ParadigmEve now treats ChatGPT's private `memcite` presentation annotation like the other
  provider-only reference markup instead of showing its boundary characters in assistant prose.
- A fresh Project chat identifies its Project in the main chat header, not only in the composer
  placeholder. The Conversations header now labels Add Project and Refresh explicitly, uses a
  conventional refresh glyph, and keeps automatic session refresh active while Pins, Plans or
  Schedule leave the Conversations sidebar visible.
- Restored exact Eve/Eva Prime identity selects its durable session on an untouched startup chat.
  When Compact & Resume transfers that exact Prime conversation A → B, the app follows the new
  owner only if the user was already looking at A; browsing another conversation is never hijacked.
- A top-level app New Chat can explicitly replace one exact ended Eve/Eva owner. The renderer only
  carries the user intent; main re-proves that the old owner is unique and ended, refuses retained
  worker-run ownership, then waits for ChatGPT's exact provider acknowledgement before a serialized
  compare-and-set moves the durable identity. Ordinary MCP/tool activity, projects, Threads/Quilts,
  helpers, schedules and ambiguous/live owners cannot steal the Eve/Eva pill.
- Plans keeps Create and Review together in the workspace header and uses the durable `%plans`
  starter for conversational onboarding. Plans → Create sends `Make me a 3 step plan to get started
  with %plans` so the first run demonstrates a real three-step durable Plan.
- `%plans` describes itself as: “Create and refine durable Plans with Eve. The plan stays near this
  app's chat window too.” Exact older shipped description text may migrate forward without replacing
  a description the user customized.
- Fresh app-authored Plan openings can be recorded just before ChatGPT publishes the first
  `turn_start`. Request Trail admission now recognizes exactly one confirmed app-owned request in
  that bounded pre-start segment and continues to reject ambiguous ownership.
- If a Plan and its first-class Plans projection are already durable but secondary Request Trail
  reconciliation fails, `update_plan` keeps the accepted Plan successful and reports the continuity
  warning instead of presenting the Plan as refused.
- The current 2.2.2 Schedule, request-trail, Computer Use recovery, model-selection, worker and
  restart guarantees remain part of the cumulative 2.2.3 tree.
- Browser-only maintenance attention now waits behind a newly recorded native user message even in
  the short gap before ChatGPT publishes its turn start, so the 22-minute heartbeat cannot answer in
  front of a fresh reboot/identity question. The Restore Eve Browser action also reopens a proven
  missing ChatGPT tab without first demanding Windows foreground focus, avoiding an unrelated
  `FOCUS_FAILED` toast when another window legitimately owns focus.
- Ordinary foreground startup now restores Chrome's durable session before reopening the exact
  durable Eve/Eva Prime. It preserves restored human/worker tabs, suppresses a redundant generic
  ChatGPT home tab when Prime is known, and opens the exact Prime only after two Companion censuses
  positively prove it absent. Unknown census fails closed so a slowly restoring Prime is not
  duplicated.
- Windows exact-Prime recovery no longer treats an omnibox write as navigation success. If UIA
  stages the exact ChatGPT URL but foreground ownership changes before Enter can commit it, recovery
  retries only the selected Eve Browser and tracks the mutated window. A successful replacement-
  window retry dismisses any orphaned old draft; terminal failure best-effort restores Chromium's
  committed address instead of leaving a URL hanging on a New Tab surface. Exact-Prime cold recovery
  also carries Companion conversation proof so a staged URL alone never counts as a recovered Prime.

### Local dogfood acceptance

For the next Windows x64 debug rollout, prove the source/tests first, then build, then let the NSIS
installer own ParadigmEve shutdown and restart. Installed-runtime evidence must separately show that
the exact Prime conversation reconnects, the dedicated browser recovers without duplicate ownership,
and the 22-minute semantic heartbeat still belongs to the exact Eve/Eva coordinator and can clear its
durable receipt normally.

Managed reinstall owns Companion materialization and browser recovery. Do not manually reload the
Companion during that flow.

### Cross-platform release contract

The public workflow still targets Windows x64/arm64, macOS x64/arm64, and Linux x64/arm64. macOS 13
Ventura or newer is the supported floor. Current macOS artifacts are **unsigned** and **unnotarized**
development/release-build outputs unless a later publishing process explicitly establishes signing
and notarization. Linux sandbox fallback documentation retains the explicit `--no-sandbox` escape
hatch only for hosts where unprivileged user namespaces are unavailable; it is not the default.

The reviewed workflow artifact names are:

- `ParadigmEve-Setup-x64.exe`
- `ParadigmEve-Setup-arm64.exe`
- `ParadigmEve-macOS-x64.dmg`
- `ParadigmEve-macOS-x64.zip`
- `ParadigmEve-macOS-arm64.dmg`
- `ParadigmEve-macOS-arm64.zip`
- `ParadigmEve-Linux-x64.AppImage`
- `ParadigmEve-Linux-x64.deb`
- `ParadigmEve-Linux-arm64.AppImage`
- `ParadigmEve-Linux-arm64.deb`
- `ParadigmEve-Extension.zip`
- `ParadigmEve-Native-Sources.tar.gz`
- `SHA256SUMS.txt`

### Release boundary

This document makes the 2.2.3 version metadata/test surface coherent; it does not by itself publish
anything. A public release still requires an exact reviewed commit/tag, the normal cross-platform
assembly and checksum gates, and explicit publication. The private x64 debug rollout may be qualified
separately as installed dogfood, with its exact installer hash recorded.
