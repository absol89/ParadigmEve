## Changes since `v2.4.1`

### Archive recording opt-out

`56e8249a` — local chat archive opt-out in three languages.

- Local session recording remains **on by default** for continuity and audit.
  It uses the existing `sessions.record` preference, not a new independent flag.
- The control appears beside **Rebuild archive** and **Open Archive Browser**,
  with explanation beneath it. It is visible through Workspace permissions,
  and discoverable from Setup and Settings.
- English, Swedish (`sv-SE`) and Latin American Spanish (`es-419`) labels
  explain the recording choice.
- Turning it off stops **new** local session message and tool-result recording.
  Goal and Loop and other recording-dependent session tools become unavailable.
- **It is not a data eraser.** Prior sessions, archive projections/static copies,
  Pins, Plans, separate logs or outputs, and ChatGPT's own history remain subject
  to their own storage rules. Earlier archives can still be opened or rebuilt.
  Local recording is optional, not a replacement for native ChatGPT memory or
  a promise that all data stays private.

See [persistence and recording](../vault/08-persistence-security-and-filesystem.md).

### Eve's links stay in Eve Browser

Links that Eve or the app opens now go to the dedicated **Eve Browser**
profile, where you choose which accounts to sign in, never to your personal
default browser. This covers Open link, saved Thread web destinations, plugin
sign-in, the local Archive, and HTML/PDF/SVG/MHTML Thread files. If Eve
Browser cannot be started, the link is not handed to another browser.
Internet shortcut files (`.url`, `.website`, `.webloc`) are shown in their
folder rather than launched. `mailto:` links and macOS privacy-settings links
still use the system handler. Computer Use is unchanged: it stays off by
default and, when you turn it on, it can see whatever is on screen.

### More reliable handoffs and receipts

`16535675` — a session reread that updates metadata no longer shifts the
completion boundary of an already finished assistant answer. Regression
coverage protects this specific behavior.

`fd9c732b` — extension journal writes are coalesced when more observations
arrive during a write, while preserving acknowledgement durability. The
Companion content/bridge also presents held or deferred Compact & Resume
handoffs honestly with their ownership and ticket context. Held is **not**
sent, accepted, or completed; this does not remove all possible browser
recovery failures.

`aec3a867` — dedicated regression tests preserve **existing** browser
eligibility, stale Companion worker ownership and revival gating. This commit
changed tests, **not** the production worker-placement algorithm.

### Fixed: heartbeat findings and Prime wakes

- **No repeated heartbeat findings.** Heartbeat maintenance retires a queued
  finding only when the exact same finding (same session and key) was already
  sent or authorized, or you removed it with **Remove queued task**. Removing
  one is durable, so it no longer comes back after Compact & Resume. The
  review is also told not to report work Prime is already doing. Different
  findings, claimed rows and possibly-sent messages are never retired by age,
  similar text or queue length.
- **Prime wakes with your personal Chrome open.** On Windows, a recovery wake
  now looks for the dedicated Eve Browser window instead of any running
  browser process. Your ordinary Chrome being open no longer counts as Eve
  Browser being present, which could leave a queued Prime wake waiting. If the
  window check cannot be completed, the wake still does nothing rather than
  touching an existing Eve tab.

### Fixed: `app.log` keeps writing after a failed write

A failed write or rotation rename (on Windows, whenever another program holds
`app.log` open) used to stop the log for the rest of the run. Unwritten lines
now stay queued in order and are retried; a partial write repeats or loses no
line; a log that cannot rotate grows to twice its limit, says so once, then
holds lines until rotation succeeds.

## Practical capabilities and boundaries

Eve's permissioned local file reads, commands, tests and supported processing
run on the user's computer rather than requiring a separate cloud-model
inference charge for each local operation. But ChatGPT tool calls, conversation,
reasoning and model access remain subject to the user's actual account limits.
Optional API services have their own billing. Eve does not silently change
the model or increase provider context or allowances.

In the user's hands-on experience, GPT-5.6 Sol Medium and GPT-6 High workflows
have *seemed* more reliable through Eve than through basic ChatGPT Plus in the
browser. This is an observation about end-to-end workflow continuity, Plans,
local state, tool evidence and recovery — not a controlled test proving the
underlying models perform differently.
