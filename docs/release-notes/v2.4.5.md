## Changes

### Source tag — runtime update and scheduled-run settling

- Electron 43.8.4 with the patched Node 24.22.1 runtime and Chrome 150 replaces
  Electron 43.8.3. The c29 Windows x64 debug candidate bundles it; c29's own
  acceptance checks are still pending.
- Queued Native findings and in-band heartbeat reviews no longer block each other
  under the composer's one-message rule, so both can reach Prime together.
- A scheduled run whose browser message was never picked up, never authorized or
  never acknowledged now ends Failed in the schedule, outbox and execution ledgers
  instead of waiting to start indefinitely. An authorized Send without an ACK is
  reported as uncertain delivery. Nothing is resent automatically. An ACKed run
  whose start was not recorded starts once on the next maintenance pass.
- A pickup expiry is now logged with its offer timing. Why the c29 browser page
  declined its first scheduled message is not yet established. This fix is newer
  than c29 and has not been verified in an installed build.
- The agent instructions moved from one large `AGENTS.md` into the Vault manual
  pages, with short routing files per source folder.

### Known acceptance limits

- One resumed-turn Native heartbeat completed its four-Plan lifecycle and
  durable receipt. A later epoch was blocked with a retained finding; subsequent
  cycles, dispatched-finding consumption and unattended idle-time execution
  remain unverified release gates.
- In-band delivery avoids an additional heartbeat Send; it cannot bypass ChatGPT's
  own tool-permission prompts or start a model turn while Prime is idle.
- Actual hosted Native child execution has been observed in a bounded manual
  read-only review, but automatic app-owned child dispatch and fully unattended
  review-to-decision progression remain unverified.
- Repeated Native to Auditable Chat and back mode switches need stronger exact-key
  retirement tests to prove old dormant heartbeat messages cannot revive.
- Electron 43.8.4 / Node 24.22.1 is packaged in c29, but c29's installed
  acceptance checks have not been completed.
- A source-only tag does not dispatch the manual installer publication workflow.
  Cross-platform packaging, GitHub pre-release publication and Latest promotion
  remain separate gates.

### Earlier candidate development history

### c18 installed — protected handoff, worker evidence

- While a source Compact & Resume answer turn remains open, periodic writing-phase
  recovery no longer reloads the source browser page. This prevents interrupting
  the answer, but does not invent `turn_end`/terminal evidence when absent. A
  one-time stuck-answer note appears after fifteen minutes of continued waiting.
- Native subagent research assignments can be tracked by Prime in a guarded
  parent-side ledger. This ledger cannot itself start native ChatGPT subagents or
  demonstrate independent native child identities, tool receipts, or permissions.
- Bounded live tests verified ChatGPT worker startup/work/message/completion and
  separately verified native subagent startup/return and one exact read-only Eve
  tool call. These do not establish unattended native execution reliability.
- The original automatic handoff's source send was recorded but source terminal
  proof was absent; it was later cancelled. A separate manual handoff committed.
  The original Prime-family move has not been verified and must never be inferred
  from a new worker family or from visible handoff prose.

### c19 source scope — selected worker mode and review ergonomics

- Automatic source handoffs wait behind the latest ChatGPT provider approval
  card, including collapsed activity. The unsent ticket remains recoverable;
  no tab focus, Stop click, or handoff Send occurs while approval is pending.
  App-side pickup also waits for a fresh exact-conversation approval signal,
  and ambiguous post-dispatch authority is not blindly retried. The 04:15
  missing source-marker receipt is not proven to be an approval race, so this
  is a preventive safeguard, not a claimed historical repair.

- **ChatGPT workers:** separate reusable helper conversations with durable Eve
  worker lifecycle and review evidence.
- **Native subagents:** delegated within an active ChatGPT Work parent, returning
  findings there rather than maintaining a separate Eve worker chat. There is no
  verified independent unattended launcher/receipt route in the Eve broker; a
  heartbeat cannot be called complete merely because Native is selected.
- **OpenRouter** and **Ollama:** explicitly chosen worker providers using a
  configured exact model and their own availability/limits. Selection cannot
  imply ChatGPT plan access or automatic model migration.
- Heartbeat reviews must use the selected mode or retain exact pending debt when
  that mode is unavailable. Reusing an existing ChatGPT review worker sends a
  compact reminder containing the exact debt key while retaining its full original
  review contract, reducing repetitive archive traffic.
- No change authorizes accepting ChatGPT's provider permission cards or replaying
  an uncertain source/destination send.

- The read-only heartbeat reviewer can report exact source-proven stale checklist items
  without receiving generic Plan edit or archive authority.
- A heartbeat with stale checklist evidence must dispatch an actionable finding; it
  cannot finish quietly as `completed`.
- The ordinary Prime can consume durable reconciliation obligations through a narrow
  direct lifecycle tool. Exact Plan revision, item IDs, scope, and full provenance come
  from durable app-owned state, not model-authored mutation arguments.
- Completed Eve heartbeat Activity archives through a single exact, revision-fenced
  helper after its final Plan projection when the existing permission allows it.
  Human Plans and unrelated Activity remain untouched.
- Session-local source cards are protected against newer same-text checklist changes.
- Existing heartbeat debt and receipt compatibility, archive authority defaults, and
  browser/model safety rules remain unchanged.

### c2 worker-coordination and live-dogfood fixes

- When the user has explicitly enabled **Allow unattributed calls**, a connector-authorized
  Eve operator may inspect and message only the installation's retained Prime worker
  family even if page request attribution is temporarily missing. The result remains
  auditable as **shared-eve / Unattributed**; shared permission never forges Prime or
  worker identity, and does not authorize spawning, finishing, or worker-lane heartbeat
  receipts. Turning the switch off restores strict exact-caller behavior.
- Exact worker-message receipts remain durable before browser wake/delivery. Distinct
  worker families with colliding names cannot be crossed by shared coordination.
- Heartbeat archive attempts now surface exact stale/revision failures. A final
  `completed` receipt is refused if auto-archive is enabled but an acknowledged,
  ready-to-archive Eve Activity of that exact revision remains Live. Human Plans
  and revoked/disabled auto-archive permission retain their existing boundaries.

### c3 provider approval, Prime continuity, and Compact & Resume

- Connector descriptions use factual platform/worker metadata, removing wording
  that could be mistaken for directions to ChatGPT's independent approval layer.
  A provider refusal before dispatch remains distinct from an Eve permission error.
- The Companion recognizes pending approval cards in the current turn even when
  **Previous activity** is collapsed. Eve records a visible waiting row and can
  show a deduplicated desktop-native notification. It never approves the card,
  replays an uncertain effect, or assumes any mobile notification was delivered.
- An approval wait holds the worker's active-turn lease. An unattributed
  Prime call with user-enabled shared-Eve authority no longer triggers an
  unsafe fallback reload; provenance stays Unattributed.
- Compact & Resume has a durable, one-shot authorization just before the
  extension creates a successor tab. A cancellation that wins first prevents
  a stale tab; authorization that wins first prevents false cancellation.
  Succession stays in the background, preserving the current tab's focus.
- A candidate upgrade starts Eve in the background with
  `--preserve-chatgpt-tabs`; it neither restarts Chrome nor navigates the
  active ChatGPT tab. The extension's existing idle-fenced refresh applies
  the new generation in-place once pages are ready. The local installer
  controller's `-SilentNoFocus` mode avoids opening a foreground NSIS wizard.

### c5 experimental shared-Eve authority (local test candidate)

- When **Allow unattributed calls** is enabled, authenticated Eve connector
  tool calls no longer wait for a ChatGPT page request-ID join before execution.
  Existing app capability and approved-root settings still apply. Proven
  exact caller identity is used when available; otherwise audit provenance
  remains **shared-eve / Unattributed** rather than claiming an exact chat.
- An opted-in shared-Eve operator can spawn into the installation's retained
  Prime worker family and can finish a worker only by supplying its explicit
  `worker_id`. The finish report identifies the shared operator rather than
  impersonating the worker. Heartbeat review workers remain outside this route.
- This opt-in mode deliberately trades exact per-chat attribution for continuity:
  without page identity, Eve cannot reliably enforce a particular chat's
  **Block** or Compact state against that unattributed call. Disable the setting
  to restore strict exact-caller enforcement. Provider approval decisions remain
  independent; c5 does not autoapprove, click, or bypass them.
- These are source and regression-test claims for a local test candidate, not
  proof of installed c5 behavior, live approval-card delivery, or browser handoff
  recovery. The previously observed compaction-repair reloads require separate
  follow-up.
