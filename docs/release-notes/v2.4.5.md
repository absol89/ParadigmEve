## Changes

- The read-only heartbeat reviewer can report exact source-proven stale checklist items
  without receiving generic Plan edit or archive authority.
- A heartbeat with stale checklist evidence must dispatch an actionable finding; it
  cannot finish quietly as `completed`.
- The ordinary Prime can consume durable reconciliation obligations through a narrow
  direct lifecycle tool. Exact Plan revision, item IDs, scope, and full provenance come
  from durable app-owned state, not model-authored mutation arguments.
- Completed Eve heartbeat Activity archives through a single exact, revision-fenced
  helper after its final Plan projection when the existing permission allows it.
  Human Plans and unrelated Activity remain untouched.
- Session-local source cards are protected against newer same-text checklist changes.
- Existing heartbeat debt and receipt compatibility, archive authority defaults, and
  browser/model safety rules remain unchanged.

### c2 worker-coordination and live-dogfood fixes

- When the user has explicitly enabled **Allow unattributed calls**, a connector-authorized
  Eve operator may inspect and message only the installation's retained Prime worker
  family even if page request attribution is temporarily missing. The result remains
  auditable as **shared-eve / Unattributed**; shared permission never forges Prime or
  worker identity, and does not authorize spawning, finishing, or worker-lane heartbeat
  receipts. Turning the switch off restores strict exact-caller behavior.
- Exact worker-message receipts remain durable before browser wake/delivery. Distinct
  worker families with colliding names cannot be crossed by shared coordination.
- Heartbeat archive attempts now surface exact stale/revision failures. A final
  `completed` receipt is refused if auto-archive is enabled but an acknowledged,
  ready-to-archive Eve Activity of that exact revision remains Live. Human Plans
  and revoked/disabled auto-archive permission retain their existing boundaries.
