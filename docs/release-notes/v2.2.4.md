# ParadigmEve 2.2.4 durable chat archive browser

## 2.2.4

2.2.4 is the private archive-browser dogfood line built from the frozen 2.2.3 source checkpoint. It
keeps bridge protocol **15** and is cumulative over the stable 2.2.2 Angel release. Local Windows
qualification uses the x64 **debug** build. The `2.2.4` tag is created only after the exact packaged
tree is installed and the live dogfood gates below pass.

### What changed

- Eve replies show in app chats again on ChatGPT's per-exchange renderer (2026-09-24). A tool-heavy
  exchange exhausted the bounded page-model walk before the reply, so only user messages and tool
  attribution were recorded; the reply is now read through its own search unit.
- "Still working" request toasts stop for work that has stopped. Request Trail `running` is written once at
  admission from the new Plan's checklist and nothing moves it, so two finished "Make me a 3 step plan" chats
  from 2026-09-23 toasted every quiet quarter hour for days. The claim now needs positive live proof: the
  origin session has not ended, its open turn's recorded start is within ChatGPT's per-turn ceiling, and the
  request is the newest from that session. Progress, review and signoff check-ins are unchanged.
- Eve replies are recorded again on ChatGPT's 2026-09-26 render-item page. Live probes showed the page no longer
  passes any message object through React props: each reply renders an `assistant-message` item (provider
  `messageId`, Markdown `content`, `phase`, `completed`) with a context carrying `isStreaming`. The Companion
  read only message objects, so its scan returned no turns and only user messages were recorded. It now reads
  that item by its unanimous provider id, final only on `final_answer` + `completed` + not streaming, and fails
  closed on disagreeing ids, another conversation or an unknown phase. Replies backfilled from earlier
  exchanges carry no provider timestamp on this page and are timed when captured.
- The installed debug build could not guarantee the reply fix above was running: Chrome keeps executing the
  unpacked Companion it loaded, and an unclean-restart launch opened the Companion browser one second before
  the app refreshed the Companion folder. The folder is now refreshed first, each materialized manifest is
  stamped with its build (`version_name`), `/hello` names that build, and a Companion running a
  different build reloads itself once (`runtime.onInstalled` re-injects the current page code).
- Restart recovery reaches a pinned Eve: automatic compaction no longer files or posts its handoff while the
  session still owes its restart wake, which previously opened a newer turn and retired the wake as moved on.
- A silent install (`/S`, for example run by Eve from inside the app) that closes the running app now starts
  the installed executable again; the updater's `--updated` handoff and `--force-run` keep their behavior.
- Native ChatGPT Project mapping is restored in both directions through an explicit, exact link on the
  Eve project (the Project's link, never its name). Chats observed inside the Project join an unbound
  session to the linked Eve project; fresh Eve chats enter the Project through a known chat's native
  Project link, or fail visibly with nothing sent.
- Expenses is now a practical phone-receipt inbox rather than a one-receipt demo path. One photo may
  contain several receipts, matching itemized/card copies are counted once, readable line items are
  preserved for later price comparisons, faded paper can still contribute a reliable date/merchant/
  total, and chain stores retain the specific printed branch/address so later advice can answer where
  to shop. Durable-item receipts may keep the exact original locally for return/warranty proof while
  ordinary groceries, restaurants and consumables remain structured ledger data only.
- `%expenses`, the built-in `#expenses` convenience alias, and **Start chat** from the Expenses Thread
  now converge on the same linked local project and shared operating playbook. A real user-created
  `#expenses` Quilt still shadows the convenience alias and keeps normal data-only Quilt semantics.
  Existing app-owned Expenses `AGENTS.md` instructions upgrade on startup only when their exact known
  hash proves they were shipped by ParadigmEve; custom project instructions and `data/ledger.json`
  remain untouched.
- Authenticated ordinary ChatGPT chats can use the installation Eve's approved workspace/project
  authority when the user's cross-chat Eve setting permits it. Exact local owner identity remains the
  preferred path, and worker/Goal-helper families remain excluded from this account-wide fallback.
- ParadigmEve now owns a durable local chat archive made from append-only/versioned semantic events
  plus SHA-256 content-addressed blobs for bytes that were actually captured. Search/index, memory
  projections and presentation HTML are rebuildable from that evidence rather than being the source
  of truth.
- The Archive workspace can rebuild and open a lightweight local ChatGPT-style static browser with
  chat selection, full transcript scrolling and local retained assets. The static site is designed
  to remain useful after app restart, computer reboot and loss of network/provider access.
- The static archive conversation list defaults to canonical newer-first chronology and has a compact
  `Newer first` / `Older first` toggle. Swedish browsers use `Nyare först` / `Äldre först`.
  Reordering the list does not renumber chat hash tokens or disturb the selected chat/search filter.
- Static archive chat hashes keep that stable sortable number first and append the original provider
  conversation route, for example `#chat-14/c/6a000003-0000-83ed-8000-000000000003`. Existing
  numbered-only `#chat-14` bookmarks remain accepted as aliases when that chat now has a provider
  route tail.
- Desktop app chrome now uses the live-measured 188px sidebar width as its default while preserving
  the 205px narrow-screen fallback and existing resize/reset persistence. The ParadigmEve brand opens
  the project GitHub URL through the existing safe external-link path, and View can open the static
  archive through the existing zero-payload archive action.
- ChatGPT-native/generated images are first-class evidence. Stable provider message/asset identity is
  recorded, already-loaded local pixels can be retained, and signed provider URLs are never promoted
  into durable archive truth. Provider-only, metadata-only, missing and capture-error states remain
  explicit.
- Reboot/offline acceptance proves retained generated-image bytes re-open from the local
  content-addressed archive with the same SHA-256 while provider-only media never masquerades as
  retained.
- Historical interrupted assistant replies no longer truncate every later archive event. Once a
  later authored user message proves the interrupted reply is no longer the current streaming
  frontier, ParadigmEve preserves that exact unfinished snapshot as immutable partial evidence and
  continues archiving later stable user/tool/final rows. The session remains visibly partial, and a
  later source-store revision cannot rewrite the published interrupted row.
- Current-frontier unfinished assistant rows are still deferred, and recoverable native-image rows
  are still withheld while local pixels may arrive. This keeps the append-only archive from freezing
  mutable evidence too early.
- Archive file publication and static-open paths reject traversal plus Windows junction/symlink/
  reparse escapes. Renderer IPC receives bounded path-free DTOs and scrubbed errors rather than raw
  local archive paths.
- Explicit user session deletion retires the corresponding archive session so the recovery browser
  does not keep presenting a chat the user deliberately removed.
- Provider-neutral memory/index and the portable `.evechat` validation seam remain separate from
  transcript truth. Existing secure artifact download and model-facing session/history tools remain
  available.

### Local dogfood acceptance

Before tagging 2.2.4:

1. qualify the exact source with the focused archive/runtime tests, typecheck, diff checks, full
   repository verification and production build;
2. build one fresh Windows x64 debug installer from that exact checkpoint and record installer and
   blockmap size/SHA-256;
3. prove the frozen public 2.2.3 installer is unchanged;
4. let the managed installer own ParadigmEve shutdown/restart while preserving restored browser
   tabs and the selected Companion profile;
5. verify the installed Archive workspace/static browser against the old interrupted
   `2.1.6 Installer Update` chat: later evidence must be visible and the interrupted capture must
   still be honestly marked partial;
6. verify static archive newer/older ordering in English and Swedish, the 188px desktop sidebar
   alignment plus resize/reset behavior, the safe GitHub brand action, and the View-menu static
   archive action;
7. verify a locally retained generated image remains readable after restart/reboot/offline without a
   provider URL;
8. verify an existing Expenses project reopens after managed restart with the same ledger revision and
   record count, its untouched app-owned `AGENTS.md` advances to the current playbook, and `%expenses`,
   `#expenses`, and Pins → Start chat all resolve the same linked project.

### Cross-platform release contract

The public workflow still targets Windows x64/arm64, macOS x64/arm64, and Linux x64/arm64. macOS 13
Ventura or newer is the supported floor. Current macOS artifacts are **unsigned** and
**unnotarized** development/release-build outputs unless a later publishing process explicitly
establishes signing and notarization.

Linux keeps the documented static sandbox fallback for hosts where unprivileged user namespaces are
unavailable. The explicit `--no-sandbox` escape hatch is a last-resort compatibility path for those
hosts, not the default launch mode.

The reviewed public workflow artifact names remain:

- `ParadigmEve-Setup-x64.exe`
- `ParadigmEve-Setup-arm64.exe`
- `ParadigmEve-macOS-x64.dmg`

### Release boundary

This document makes the 2.2.4 source/version/manual surface reviewable; it does not publish a
release. Do not move or recreate the frozen `2.2.3` tag, overwrite its public installer, merge the
experiment branch to `main`, or create `2.2.4` merely because source tests pass. The final tag
belongs on the exact source that produced the installer which passed installed-runtime dogfood.
