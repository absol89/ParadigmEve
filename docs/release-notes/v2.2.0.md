# ParadigmEve private dogfood release candidate

## 2.2.0

This candidate is the Free/default-install regression release. It keeps the known-good `%Threads`
checkpoint and integrates three bounded, regression-first repairs: native Free/default model handling,
Windows Computer Use recovery truth, and first-install connector/tool verification.

## Why this build exists

Focus testers cannot be assumed to have ChatGPT Plus. The release therefore treats a genuinely fresh
Free/default account as the primary acceptance baseline and keeps provider-native behavior intact
instead of manufacturing a paid model identity or widening local permissions to make setup look green.

The source/test gate is deliberately separate from provider/device dogfood. A passing local test can
prove Eve’s own ownership and persistence rules; only the signed-in Eva/Free UI can prove current
provider entitlement, native model/Think presentation, real connector invocation, installed Computer
Use behavior, and reinstall/session recovery.

## What changed

### Native Free/default model behavior

- A genuinely fresh unselected chat may keep `model=null` and `reasoningEffort=null` when model
  discovery is missing, stale, or still pending. Eve does not invent a paid model identity.
- When that fresh send succeeds and becomes a durable session, Eve records the exact native/default
  browser-send intent. Follow-up sends in that same conversation remain provider-native even if model
  discovery is still unavailable, while a later explicit model selection remains authoritative.
- Native Think remains a provider-owned mode rather than being translated into “High reasoning.”
- Explicit existing-session/model selections stay fail-closed and still require exact current native
  confirmation.
- Model-catalog discovery now has exact MV3-persistent custody across service-worker restart and
  releases that custody only after an accepted observation.
- Startup’s unknown-catalog discovery is passive and cannot open another ChatGPT tab by itself.

### Keyboard-safe Thread / Quilt vocabulary

- `%thread` activates one specific Thread and its standing prompt + Pins.
- `#quilt` addresses a wider Quilt of Threads for broad saved-Pins context without activating the
  member Thread prompts.
- Quilts use the ordinary `#` key. The product does not teach or require a symbol that is absent
  from ordinary American/English keyboard layouts.
- Legacy internal names such as `quiltId` remain storage compatibility details and are not user syntax.

### Computer Use robustness

- Zero/all-excluded Windows discovery is an actionable `NO_TARGETABLE_WINDOWS` condition instead of a
  false healthy surface.
- Exact native app identity remains mandatory. Identityless/inaccessible windows are not promoted to
  model input authority and there is no process-name fallback.
- Closed-window and helper-generation changes retire stale coordinate/index/ref authority. Fresh
  `list → state → input` observation is required before new input can succeed.
- Screen/control permission changes retire disposable model-facing Window2 contexts at the durable
  Settings transition, including an offline Off → On cycle.
- Fresh installs still leave Computer Use off; enabling it remains an explicit user choice.

### First-tool onboarding truth

- Durable onboarding no longer treats connector scanning/listing as end-to-end verification. Each
  required non-optional surface needs both request/discovery evidence and a recognized external tool
  invocation.
- Overall and per-surface tool clocks are advanced coherently before the first-tool transition is
  published, so setup promotion cannot strand on a partial snapshot.
- Authenticated self-test and tunnel-probe calls remain internal evidence and cannot satisfy setup.
- Broker-owned local workers may use the same Core handlers but cannot mint external ChatGPT
  first-tool evidence. Genuine external direct and nested/code-mode calls remain eligible.
- A recognized external call may count even when it safely refuses because of a missing root or
  disabled capability: onboarding is proving tool routing, not successful mutation.
- Release dogfood uses a stricter separate gate: one harmless Eve tool must actually succeed.

### Fresh/default permissions

- Fresh config continues to start with `roots=[]`.
- Filesystem work remains blocked until the user explicitly approves a root.
- Screen, control, and clipboard Computer Use permissions remain off on a fresh install.
- No permission is broadened merely to satisfy onboarding or tests.

## Required debug-build acceptance

The laptop/local artifact for this candidate is a Windows x64 **debug** installer. Before calling it
ready for dogfood:

- package, lockfile, Companion manifest, `APP_VERSION`, Vault and release notes must all identify
  **2.2.0**;
- focused B/C/D regressions, fresh-install acceptance, typecheck and repository verification must pass;
- the Windows x64 debug NSIS build must finish successfully;
- packaged-runtime smoke must pass against the produced payload;
- the installer and blockmap must be hashed and archived as 2.2.0 evidence.

Bridge protocol remains **15** because 2.2.0 does not change the browser wire contract.

## Eva / ChatGPT Free dogfood boundary

Use the real current Eva/second-desktop account state rather than substituting Plus:

1. Establish whether ChatGPT Free currently exposes the custom ParadigmEve connector path.
2. Confirm connector discovery.
3. Run one harmless Eve tool successfully; rootless/read-only `work_context {}` is preferred when
   available.
4. Approve only the minimal temporary filesystem root needed for any read test.
5. Confirm a fresh native default remains provider-owned and native Think behaves as the provider
   exposes it.
6. Enable Computer Use explicitly, then prove `list_windows → get_window_state → input`.
7. Close/re-list/re-observe and prove stale coordinate/index/ref authority is rejected.
8. Exercise helper/restart recovery and then reinstall/session recovery without discarding the
   user’s restored Chrome session.

If ChatGPT Free blocks the custom connector/MCP path, record that exact provider boundary. Do not
silently use Plus and call it Free acceptance, and do not design a broad alternate transport from
documentation alone.

## Platform notes

The release binaries are **unsigned**; macOS builds are also **unnotarized**. macOS requires
**macOS 13 Ventura or newer**. Ad-hoc sealing verifies bundle integrity but does not establish
publisher trust, so verify the matching SHA-256 checksum before running a downloaded artifact.

On Linux, prefer the DEB on Debian/Ubuntu. If a host disables **unprivileged user namespaces**,
the AppImage launcher can use its documented conditional `--no-sandbox` fallback. That fallback is
not the default launch mode.
