# ParadigmEve 2.3.1 — Compact & Resume that finishes the move

## 2.3.1

ParadigmEve 2.3.1 is a focused reliability update for long-running Eve conversations.

The main fix is **Compact & Resume**. A fresh replacement chat could sometimes receive the handoff successfully, start working, and still leave ParadigmEve showing **Opening a fresh chat** because ChatGPT had not exposed the newly sent user message to the Companion yet. The local session then stayed attached to the old chat even though the new chat already existed.

2.3.1 closes that gap. After the native Send succeeds, the Companion can use Chrome's own conversation route as a narrowly fenced fallback when the exact authored message has not appeared yet. It only does that while the original fresh-send attempt is still alive, the same browser document still owns the command, the route is not the source conversation, and there has been no trusted user interaction that could have retargeted the page.

For normal use, the result is simple: **when Compact & Resume opens the new chat and ChatGPT accepts the handoff, Eve can finish moving the session there instead of getting stuck between chats.**

- **Most Windows PCs:** `ParadigmEve-Windows-x64-debug.exe`

`SHA256SUMS.txt` on the release page lets you verify the download before opening it.

The beta builds are still unsigned, so Windows SmartScreen or macOS Gatekeeper may warn before opening them. Make sure the file came from this repository.

## What changed in 2.3.1

- **Compact & Resume no longer depends on the first sent message appearing immediately in ChatGPT's page model.** If ChatGPT has accepted the send and Chrome already knows the new `/c/<conversation>` route, ParadigmEve can finish the handoff from that browser-owned route.
- **The fallback stays inside the original send attempt.** It is disabled after trusted mouse or keyboard interaction, refuses the source conversation, and requires the same authorized browser document/navigation owner.
- **Chrome's current and pending routes are handled together.** This covers the transition where the old conversation is still visible in `url` while the newly created replacement conversation already exists in `pendingUrl`.
- **Ambiguous sends remain ambiguous.** If there is no concrete replacement route, ParadigmEve keeps the durable `dispatched-unresolved` handoff instead of replaying the prompt or guessing where it went.
- **The exact message remains the stronger proof.** The route fallback commits the conversation identity only; it does not invent a ChatGPT message id. If the marked Resume message appears later, its real identity can still be reconciled normally.

The fix includes regression coverage for the route-only success case, delayed source-to-destination routing, stale browser documents, and a trusted human retarget to an unrelated conversation.

## Updating from an earlier version

- **From 2.3.0 or 2.2.9:** the built-in updater can find and install 2.3.1 normally once the release is marked latest.
- **From 2.2.8 or older:** those versions only know the older `ParadigmEve-Setup-…` Windows installer name. Update through 2.2.9 first, or download the 2.3.1 `ParadigmEve-Windows-…` installer manually. Your settings, folders, chats, and local history are kept.

2.3.1 includes everything from 2.3.0, including Windows-named installers, idle-safe Companion self-update, and the Expenses receipt-recording fix. See the **[2.3.0 release notes](v2.3.0.md)** for those changes.

## First time using Eve?

The setup and permission model did not change in 2.3.1. The full first-user walkthrough is in the **[2.3.0 Meet Eve guide](v2.3.0.md)** and the **[setup reference](../setup.md)**.

A fresh install still starts with no approved folders and Computer use off. File access stays inside folders you approve; **Run commands** is a separate, broader permission. You can turn on more Eve authority, workers, startup, and Computer use when you want them.
