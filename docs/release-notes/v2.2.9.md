# ParadigmEve 2.2.9 — Meet Eve

## 2.2.9

ParadigmEve gives ChatGPT a place to keep working with you instead of forgetting the practical parts every time a chat gets long.

Eve can work with folders you choose, run commands, keep Plans and saved context, use helper chats for longer jobs, recover after a restart, and — if you allow it — look at and control desktop apps for you.

The important bit is that **you decide how much access she gets**.

> ParadigmEve is beta software and the current builds are unsigned. Start with one ordinary folder, get comfortable with the setup, and only turn on the extra access you actually want.

## Download the right file

Open the **[ParadigmEve releases page](https://github.com/absol89/ParadigmEve/releases)** and choose the 2.2.9 build for your computer.

- **Most Windows PCs:** `ParadigmEve-Setup-x64-debug.exe`
- **Windows on ARM:** `ParadigmEve-Setup-arm64-debug.exe`
- **Apple silicon Mac:** `ParadigmEve-macOS-arm64-debug.dmg`
- **Intel Mac:** `ParadigmEve-macOS-x64-debug.dmg`
- **Linux:** choose the x64 or arm64 `.deb` / AppImage that matches your machine

There is also a `SHA256SUMS.txt` file on the release if you want to verify the download before opening it.

Windows SmartScreen and macOS Gatekeeper may warn you because the beta builds are not publisher-signed yet. That warning is expected, but you should still make sure you downloaded the file from this repository.

## First launch: the short version

You only need to do four things before Eve can help with real work:

1. **Give Eve one folder to work in.**
   Open **Settings → Workspace → Folders → Add** and choose a folder you are happy for Eve to use.

2. **Connect ParadigmEve to ChatGPT.**
   Open **Settings → Setup** and follow the six setup steps. The recommended connection is **OpenAI Secure MCP Tunnel**.

3. **Add the Companion extension.**
   Setup has a button called **Open extension folder**. In your browser's Extensions page, turn on Developer mode, choose **Load unpacked**, and select that folder. Then open or reload ChatGPT.

4. **Add Eve in ChatGPT.**
   Setup links you to ChatGPT's Developer mode and connector page. After saving Eve, open **ChatGPT → Settings → Plugins → Eve → Permissions**. For most people, **Allow low risk actions** is the best starting point.

Then open Eve, choose a project, and ask for something real. For example:

> Read this project, tell me what it does, and make a Plan for the first thing you would improve. Don't change anything yet.

That gives you a useful first run without handing over every permission at once.

## What starts safely limited

ParadigmEve does not treat installation as permission to roam around your computer.

On a fresh 2.2.9 install:

- **No folders are approved yet.** Eve cannot start reading your documents just because the app is installed.
- **Computer use is off.** **See the screen**, **Control mouse and keyboard**, **Read clipboard**, and **Write clipboard** all start off.
- **Eve cannot change ParadigmEve settings**, **archive completed Eve work**, or **control ParadigmEve itself** until you allow those things.
- **Start ParadigmEve when I sign in** and **Connect automatically at startup** start off.
- **Goal and Loop** do not start running on their own.
- Workers are available, but exact chat identity is still required; the more relaxed **Allow unattributed calls** option starts off.
- The normal Core permissions, including file changes and **Run commands**, start available. File tools still have no folder to touch until you approve one.

Ordinary file abilities are available to the Eve connector, but file reads and edits still stay inside the folders you approved. With no approved folder, there is simply nowhere for those file tools to work.

**Run commands is stronger, and it starts on.** A command still needs an approved workspace as its starting point, but once it runs it uses your normal computer account and is not a filesystem sandbox. An approved folder does not magically stop a shell command from reaching elsewhere on your machine. If you want the strictest first-time setup, open **Settings → Workspace → Permissions** and turn **Run commands** off until you actually need it.

One convenience is already on: **Allow Eve in other ChatGPT chats and devices**. That lets another ChatGPT conversation using your Eve connector reach the same local Eve. If you want strict main-chat-only access instead, turn that switch off.

## The everyday setup I recommend

This is close to the setup I use for Eve myself. You do **not** need all of it on day one.

### 1. Give Eve the folders you actually work in

Go to **Settings → Workspace → Folders** and add your project folders or a sensible parent folder.

Do not approve your whole drive just to avoid thinking about it. A few useful folders make file access easier to understand and limit what the file tools can touch. Remember that **Run commands** is a separate, broader permission.

### 2. Turn on Computer use when you want Eve to help across apps

In **Settings → Workspace → Permissions**, enable the Computer use permissions you want:

- **See the screen**
- **Control mouse and keyboard**
- **Read clipboard**
- **Write clipboard**

If you only want Eve to inspect a window, you can leave control and clipboard access off. If you want the smoother “open the app, click the thing, paste the result” experience, enable all four.

### 3. Let Eve stay available

In **Settings → Setup → Advanced — method, program, startup**, I recommend turning on:

- **Start ParadigmEve when I sign in**
- **Connect automatically at startup**

That way Eve is usually there when you open ChatGPT instead of needing a little setup ritual every time.

**Keep running in the tray when closed** is personal preference. Turn it on if you want closing the window to leave Eve available in the tray.

### 4. Decide how much authority Eve should have over Eve

Still under **Settings → Setup → Advanced**, there is an **Eve authority** section.

For the smoothest hands-off setup I use:

- **Allow Eve in other ChatGPT chats and devices** — on
- **Allow Eve to change ParadigmEve settings** — on
- **Allow Eve to archive completed Eve work** — on
- **Allow Eve to control ParadigmEve** — on

The last switch also allows Computer use inside the ParadigmEve app, so it is intentionally not a default.

If you are new, turning these on one at a time is perfectly fine. None of them are required just to chat with Eve or work inside an approved folder.

### 5. Let Eve use helpers on longer jobs

Open **Settings → Agents & automation → Workers & recovery**.

The setting called **Sub-agent workers** is the most helper chats Eve may use in one run. A fresh install starts at **2**. I normally use **4** so Eve can split up a bigger job instead of going quiet while doing everything in a single chat.

If your ChatGPT account starts rate-limiting worker chats, put this back to 2.

I would leave **Recover other chats’ tabs** off unless you specifically want ParadigmEve reopening ordinary work chats after they disappear.

**Allow unattributed calls** is more permissive: it lets some self-contained work continue when the Companion cannot prove exactly which chat sent it. I use it on my own setup, but I would leave it off until your Companion connection is stable and you understand the tradeoff.

## ChatGPT's own permission switch

ParadigmEve and ChatGPT each have their own permission boundary.

After adding Eve in ChatGPT, open:

**ChatGPT → Settings → Plugins → Eve → Permissions**

I recommend **Allow low risk actions** for normal use. ChatGPT can let ordinary low-risk actions through and still stop on things it considers more sensitive.

If you deliberately want long Goal, Loop, coding, or worker jobs to continue without those ChatGPT approval stops, you can choose **Allow all actions**. ParadigmEve's own folder and Computer use permissions still apply either way.

## What Eve can do once you are set up

You do not need to learn special commands before using Eve. Talk to her normally.

Useful things to try:

- “Read this folder and explain what I'm looking at.”
- “Fix this bug, run the tests, and show me what changed.”
- “Make a Plan for this and keep it attached while you work.”
- “Split the research into a few workers and bring the useful parts back here.”
- “Save this message so we can use it again later.”
- “Remind me what we were doing before this chat got too long.”
- “Open the app and check the setting for me.” — if Computer use is enabled.

Eve can ask helper chats to work on separate pieces of a bigger task. Those helpers report back to Eve; **Eve stays the conversation you are working with**.

## A few things worth knowing

- ParadigmEve keeps local session history so work can survive restarts and long-chat handoffs.
- **Compact & Resume** can move a long-running session into a fresh ChatGPT conversation without throwing away the local project, Plan, or worker history.
- Your approved folders and local settings stay on your machine.
- Credentials are stored using your operating system's secure credential storage.
- ParadigmEve is still beta software. Keep backups of anything important and review the actions it takes, especially while you are getting used to it.

## What's better in 2.2.9

This release is mostly about Eve being steadier when the work gets bigger:

- Eve has stronger habits for changing code carefully and proving that a fix really worked.
- Eve notices long or parallel jobs sooner and uses helper chats instead of disappearing into one long serial task.
- Windows update handling is more forgiving about installer names, which makes future upgrades less brittle.
- The public macOS download list is simpler: DMGs are the install files, without duplicate ZIP downloads beside them.
- The manual and release guidance have been brought back in line with how the current app actually works.

For the full running history, see the **[CHANGELOG](../../CHANGELOG.md)**.

## Platform notes and release files

Most people only need the installer for their own computer. The full public 2.2.9 release contains:

- `ParadigmEve-Setup-x64-debug.exe` — Windows x64
- `ParadigmEve-Setup-arm64-debug.exe` — Windows ARM64
- `ParadigmEve-macOS-x64-debug.dmg` — Intel Mac
- `ParadigmEve-macOS-arm64-debug.dmg` — Apple silicon Mac
- `ParadigmEve-Linux-x64-debug.AppImage` — Linux x64 portable app
- `ParadigmEve-Linux-x64-debug.deb` — Linux x64 package
- `ParadigmEve-Linux-arm64-debug.AppImage` — Linux ARM64 portable app
- `ParadigmEve-Linux-arm64-debug.deb` — Linux ARM64 package
- `ParadigmEve-Extension.zip` — standalone copy of the Companion extension
- `ParadigmEve-Native-Sources.tar.gz` — corresponding native-library source bundle
- `SHA256SUMS.txt` — checksums for the public downloads

**macOS 13 Ventura or newer** is the supported Mac floor. The current Mac builds are **unsigned and unnotarized**, so Gatekeeper may warn before opening them.

On Linux, the AppImage normally uses the system sandbox. On hosts where **unprivileged user namespaces** are unavailable, it can fall back to `--no-sandbox`. That is a compatibility fallback, not the normal launch mode.
