# ParadigmEve 2.2.6 — Compact & Resume on ChatGPT's current layout

## 2.2.6

2.2.6 is cumulative over 2.2.5 and keeps bridge protocol **15**. It repairs Compact & Resume on ChatGPT's
render-item layout.

### Fixed

- ChatGPT renders each user message as a render item (`props.item = { type: 'user-message', messageId,
  serverMessageId, message }`, probed live 2026-09-27). The Companion read only assistant items, so the
  Compact & Resume markers in user messages were never found: every automatic compaction sent its handoff,
  ChatGPT wrote a full brief, and the ticket stayed `dispatched-unresolved` until cancelled. User items are now
  adapted by their provider id, accepted only when `serverMessageId` agrees and the item is the user message its
  exchange is keyed by, with the exact authored text.
- A finished assistant render item (final answer, completed, not streaming) is now a stable message by its
  provider id, which Compact & Resume requires of a brief. Streaming items stay unstable.
- The user-facing platform notes moved from the README to `docs/setup.md`.

### Local dogfood acceptance

Before tagging 2.2.6 as dogfooded: install the Windows x64 debug build, let an automatic compaction run in a
long chat, and confirm the ticket collects the brief and resumes in a new chat.

### Cross-platform release contract

The public workflow still targets Windows x64/arm64, macOS x64/arm64, and Linux x64/arm64. macOS 13
Ventura or newer is the supported floor. Current macOS artifacts are **unsigned** and
**unnotarized** development/release-build outputs unless a later publishing process explicitly
establishes signing and notarization.

Linux keeps the documented static sandbox fallback for hosts where unprivileged user namespaces are
unavailable. The explicit `--no-sandbox` escape hatch is a last-resort compatibility path for those
hosts, not the default launch mode.
