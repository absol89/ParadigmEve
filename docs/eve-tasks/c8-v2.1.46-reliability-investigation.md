Date: 2026-10-26. Status: read-only investigation complete; proposed changes are **not implemented or tested**. No c8 candidate was built or installed.

## Scope and provenance

- Eve checkout: release/2.4.5, HEAD 63167753a8fac59cac90162fc6c997d5818b37c1. Existing 34 dirty/untracked paths preserved.

## Executive decision

Reliability work is justified, but the upstream release should **not** be merged wholesale. Eve already has substantial exact-document, selected-tab, durable-input and worker-revival safeguards. Port only source-proven missing invariants and add negative tests at their existing owners.

## 1. Stream and stalled-page recovery — worker-11

Upstream:
- [e5250c8](https://github.com/totec448-spec/chat-on-steroids/commit/e5250c840deb4bdecb2c7ab631511eefd8a6b658): metadata changes on a known tool message no longer count as stream recovery progress.
- [87d75a0](https://github.com/totec448-spec/chat-on-steroids/commit/87d75a03624012a1d3318c66ad6320ed12b1687a) and 154381b: process-memory pageless verdict, periodic controls refresh, stopped caption.
- [ff440ef](https://github.com/totec448-spec/chat-on-steroids/commit/ff440efee20aefb9a32af142c908dd8e9a80692e): finite unclaimed repair-offer budget across episodes.

Eve evidence:
- extension/content.js:4258-4268 calls noteTurnProgress on changed tool/request-ID/answered/owner signature; lastChangeAt at 655-659 influences the stalled outcome at 2102-2112 and 2739-2743. A metadata-only re-emission can be false progress.
- bridge.ts:1634-1695 session controls has no pageless verdict. At 8464-8509 handed-but-unclaimed repair offers can be requeued with fresh tokens; renderer/chat.ts:1278-1322 and 2775-2819 can keep cached Working state without an independent controls refresh.
- Already present: extension/background.js:3602-3614 protects selected/audible/draft pages, 3625-3678 probes stream/error state, 3723-3737 rechecks before reload; bridge.ts:6110-6177 has activity/grace controls, 1861-1914 guards restart wake, and 4834-4925 tracks worker lifecycle. Relevant tests already exist in extension.test.ts, bridge.test.ts and content-script.test.ts.

Negative acceptance tests:
1. A known tool message with only request-ID/owner metadata changed does not refresh the stall clock; first appearance and unanswered-to-answered do.
2. More than the allowed unclaimed repair offers lead to one durable pageless/stopped outcome, not indefinite fresh tokens; a real exact-page activity poll can lift it.
3. Selected, drafted, Voice-active or still-loading pages are deferred, never called absent and never reloaded as a shortcut.
4. Renderer controls refresh without new page events, stop an expired Working caption, and reject a late response from a previously selected chat.
5. Restart wake respects supersession, active tool, streaming, exact owner and send receipts.

## 2. Restart wake, tool latency and queues — worker-12

Upstream 86f4e81d, 521b5d44, e253d96a introduced route-settle behavior: a first eligible existing-chat send after a new tunnel client waits for route readiness with bounded learned timing, associating new MCP ingress with the observed page request. Upstream 6bcfce1d and aa71137b avoid unnecessary metadata writes when merely reading queued events.

Eve has no equivalent route-settle owner; bridge.ts claims pending browser input without a first-after-takeover gate. An old provider route could delay an existing-chat call despite healthy Chrome. This is a source-level possibility, not a reproduced cause of the user's queued wakes.

Already present:
- recovery-memory.ts:273-332 creates exact restart identity and deterministic outbox UUID.
- session/input.ts:664-667, 2021-2059 prioritizes restartWake and bypasses stale future dueAt.
- bridge.ts:2305-2319, background.js:2217-2245/2360-2364/2508-2526/3367-3389 and content.js:12032-12060 protect idle exact document, composer, Voice and typing.
- index.ts:1050-1062 reoffers unclaimed wake; bridge.ts:1860-1914 has bounded escalation.
- agents.ts:3156-3246, 3437-3460, 4860-5043 and bridge.ts:4230-4252/4291-4317 preserve worker wake lease/ACK and restart custody.

Potential latency: session/store.ts:434-450 flushSession also writes metadata; readEvents and readRecentEvents call it. No live timing measurement establishes user-visible latency.

Negative tests: fake-clock first existing-chat versus fresh chat; multiple tunnel clients; exact request association only, pre-send requests ignored, bounded learned fast/late updates and malformed persisted state; one outbox UUID across restart, future dueAt bypass, crash before/after claim and ACK, duplicate ACK and old-final races; immediate ordered event reads without premature metadata write, with quit flush. No automatic replay of ambiguous sends.

The worker's direct /appdata read was refused as INVALID_ARGUMENT. **Actual live main-Eve wake queue contents and installed-runtime drain state remain unverified.** Do not raw-edit that managed state.

## 3. Compact, browser ownership and Project edge cases — worker-13

Upstream c31e8923/5fdf2ace normalizes rich-preview editor content; a2266e79/ded8c4f6 gates new work to chosen browser; 70db54ba includes Continue failure details; 2d2af973/448b74b2 terminates deleted-Project loading.

- **Missing rich-link handling:** Eve extension/chatgpt-dom.js captureComposerDraft (around 811), insertPrompt (around 1998), clearPromptExact (around 2046) and extension/content.js bootstrap still use raw composer text that can include rendered preview markup. Compare canonical authored text excluding injected style/script/noscript/template, while retaining attachment identity and source/destination checkpoints.
- **Missing chosen-browser handout gate:** bridge.ts /activity, /status and /compact routes can hand out work without a per-request chosen-browser check. Existing placement constraints do not establish that all handouts use the user-selected Eve Browser.
- **Partial Continue error detail:** extension/background.js and bridge.ts input-failure handoff do not consistently propagate a bounded actionable reason; avoid leaking raw browser text.
- **Partial deleted Project case:** exact entry errors are handled, but a Project-home loading state may wait indefinitely without an absence verdict.

Tests: Drive rich preview + styled wrappers through source capture and destination verification; no duplicate Send. With multiple browsers open, only chosen browser claims/starts workers, with no navigation or focus stealing. Continue failure reason survives to activity once and is scrubbed of secrets. Deleted Project, slow Project, temporarily disconnected Project and missing native entry produce distinct bounded outcomes.

## 4. Approvals, identity and privacy — worker-14

- **PR #1844 partial/mostly ported in c7:** Eve src/main/mcp/instructions.ts now emits factual enabled capabilities and neutral ChatGPT refusal text; test/mcp-user-instructions.test.ts covers it. The *complete* Core/Plugins/Desktop emitted instruction text across operating systems, allowlist and skills still needs a no-self-ranking regression. ChatGPT's provider-side approval decisions remain external; the user's repeated cards are not disproved by the c7 source patch.
- **Passive approval detection implemented:** extension/chatgpt-dom.js:888-904, content.js:6452, bridge.ts:2767-2773, approval-wait.ts:32-67 and index.ts:508-525 detect and notify on a pending card, including collapsed state. There is no autonomous approval path. Upstream #1851 cf4a64f4/7bfbb2d4 separates label/value in approval-card rows; Eve lacks a complete parser/presentation path. Any future click feature requires a separate explicit product decision and exact visible human consent.
- **General outbound secret shield missing:** Upstream #1797 6cec3c90 and follow-ups redact token, JWT, private-key and configured-secret patterns before model delivery. Eve recorder and plugin output have some redaction (redaction.ts, plugins/manager.ts), but mcp/kernel.ts:913-968 does not provide a general shield for Core read/exec/write_stdin text and structured results. Mask before external delivery and recording; preserve real values only within authorized computation; do not mutate images or opaque hashes.
- **Multiple connector identities partially safe:** chatgpt-dom.js:2233-2277 and content.js:11855-11953 validate exact app/surface/route and fail closed on multiple candidates. plugin-refresh.ts:182-232 revalidates. Distinct valid same-name unenrolled connections remain ambiguous; never guess or click twice after uncertain result.
- **Non-ChatGPT subagents mostly fail closed:** agents.ts:1925-1935 refuses unidentified spawning, while tools-core.ts shared-Eve opt-in remains distinct. Upstream #1848 0b7664ef gives an explicit no-chat error; improve wording for stateless request-only clients without broadening authority.

Tests: synthetic credential fixtures across Core file/command/background result and nested structured output; redacted model/recorder paths agree; repeat, hidden, stale and duplicate approval cards do not produce clicks; provider rejection is not called human Deny; connector duplicate IDs/names/surfaces and lost click receipts fail closed; unrelated stateless request IDs cannot gain another worker family.

## Recommended order and acceptance gate

1. **Security boundary first:** general Core outbound secret shield, with preservation of nested-tool true values and privacy-safe logs.
2. **First reliability tranche:** meaningful stream progress + bounded pageless verdict/renderer refresh; learned tunnel route-settle for the first eligible existing-chat send.
3. **Handoff tranche:** rich-preview normalization, chosen-browser handout fence, bounded Continue error receipt and deleted-Project loading verdict.
4. **Performance and diagnostics:** event-read metadata batching, no-chat caller message, emitted instruction audit and approval-card display regression.
5. Run focused regression suites, TypeScript/diff check, full verify:ci, then build a uniquely numbered candidate only after implementation authorization and a separate candidate decision. Keep c7 and its installed data intact.
6. Live acceptance after installation: four-worker launch/receive/finish without wrong browser, selected-tab reload, duplicate send or wrong Prime owner; restart with outstanding main-Eve wake; broken stream and pageless verdict; rich link in Compact & Resume; actual provider approval card behavior. A provider-side card may remain even when Eve is correct. Never autoapprove or infer user Deny from a TOOL_REJECTED receipt.
